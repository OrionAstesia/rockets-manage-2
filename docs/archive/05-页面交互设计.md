## 1. 文档目的与设计原则

### 1.1 本文档要解决什么

`04-接口与路由设计.md` 回答「有哪些地址、返回什么」；本文回答**「玩家看到什么、点什么、点了之后发生什么、没数据时看到什么」**。本文是 `templates/` 与 `static/js/`、`static/css/` 的直接施工图。

本文不定义字段（以 brief 第 4 节为准）、不定义 URL 与视图签名（以 brief 第 6 节与 `04` 为准）、不推导公式（以 brief 第 8/9 节与 `06` 为准）。

### 1.2 设计目标：四个动词

| 动词 | 玩家此刻的状态 | 对应页面 | 设计判据 |
|---|---|---|---|
| **记录** | 「我刚造完一枚火箭/一个引擎，先记下来」 | 火箭编辑、载荷编辑、部件、发射场 | 录入表单要**少字段、可折叠、有默认值**；编号 `code` 必须能自动生成建议值 |
| **安排** | 「我打算在 UT 420000 发射，别让我忘了」 | **发射日程**、发射新建 | 计划时间 `planned_ut` 是**一等公民**，任何时候都能一眼看到「下一条要发的是什么」 |
| **统筹** | 「整个 Duna 计划现在到哪一步了，钱花了多少」 | **计划总览** | 1:n 聚合页必须**一次请求就看完所有成员**，不需要跳 5 个页面 |
| **查看在轨资产** | 「我 Kerbin 上还有几个东西在飞，周期多少」 | 在役航天器列表/详情 | 列表页直接算出**周期与近远拱点**，不允许玩家自己按计算器 |

### 1.3 八条设计原则

| # | 原则 | 具体落地 |
|---|---|---|
| P1 | **信息密度优先** | 玩家在 PC 上玩 KSP，旁边开着本工具，屏幕够宽。列表页一屏尽可能多行，`table-sm` 为默认；详情页把计算值集中到「摘要条」而不散落在页面各处 |
| P2 | **少点击** | 任何「详情」页必须能直接跳到「编辑」；任何列表行的主键文字即链接；`+ 新增` 按钮固定出现在列表页右上角；不用二级菜单套二级菜单 |
| P3 | **表格 + 卡片为主** | 集合用 `table`（可排序、可筛选、密度高），聚合/摘要用 `card`。**不使用轮播、折叠面板做主要信息容器**（折叠 = 多一次点击） |
| P4 | **数值必须带单位** | 界面上任何数字都要有单位后缀：`3 100 m/s`、`40.0 t`、`200 kN`、`345 s`、`2 863 km`。裸数字视为缺陷 |
| P5 | **计算值要视觉突出** | Δv、TWR、周期、近远拱点一律用「大字号 + 等宽数字 + 单位小字」呈现，与录入字段在视觉层级上分开（详见第 7 节） |
| P6 | **录入值 vs 计算值并列显示** | `CarrierModel.max_payload_mass`（声明）与计算运力、`Spacecraft.cached_period_sec`（抄录）与计算周期，**并排两个列/两个数字**，不一致给提示，绝不互相覆盖 |
| P7 | **桌面优先，响应式基本可用** | 断点策略见 1.4。不做移动端专属交互（不做底部 Tab 栏、不做手势） |
| P8 | **无构建链是硬约束** | 所有 JS 是能直接放进 `<script>` 的 ES2017 原生语法；模板复用靠 Django `{% include %}`；不引入任何需要编译的前端产物 |

### 1.4 响应式策略（桌面优先）

| 断点 | Bootstrap 类 | 布局变化 |
|---|---|---|
| `≥1400px` | `container-xxl` | 主容器最大宽 `1320px`；表单页「标签 + 控件」两栏；列表页侧栏筛选器常驻右侧 |
| `1200–1399px` | `container-xl` | 同上 |
| `992–1199px` | `container-lg` | 侧栏筛选器移到列表上方（`col-lg-3` → `col-12`，用 `order-*` 调整） |
| `768–991px` | `container-md` | 表格横向滚动（`.table-responsive`）；火箭编辑页的级行改为卡片堆叠 |
| `<768px` | `container-fluid` | 导航折叠为汉堡菜单；不保证复杂表单（级 FormSet）好用，**只保证能提交不报错** |

**明确不做**：移动端拖拽排序（触屏 HTML5 `draggable` 支持差，降级为「上移/下移」按钮，见第 5 节）。

### 1.5 无构建链下的技术约定

| 事项 | 约定 |
|---|---|
| CSS | `static/css/style.css` 单文件，Bootstrap 5.3 CDN 在前，本地样式在后覆盖 |
| JS | `static/js/stage_formset.js`（级表单）、`static/js/orbit_calc.js`（轨道实时计算）、`static/js/common.js`（删除确认、筛选器自动提交、tooltip 初始化），全部**原生 ES2017**，用 `DOMContentLoaded` 或在 `<body>` 末尾 `<script>` |
| 模板复用 | `{% include %}` + `{% block %}`；无组件库 |
| 动态行 | HTML `<template>` 标签 + `cloneNode(true)`（见第 5 节），**不用** innerHTML 字符串拼接（避免 XSS 与转义混乱） |
| Bootstrap JS | 仅 `bootstrap.bundle.min.js`（含 Popper），用于 `modal` / `tooltip` / `collapse` / `dropdown`。**任何页面在 Bootstrap JS 加载失败时，核心功能（提交表单、跳转链接）必须仍然可用** |
| 图标 | Bootstrap Icons（理由见 8.5） |
| AJAX | 原生 `fetch()` + `FormData`，CSRF 取自 `{% csrf_token %}` 或 cookie；不做请求重试和加载骨架 |

## 2. ★ 信息架构与导航设计

### 2.1 玩家的心智模型 → 导航分组

玩家的四个动作（记录/安排/统筹/查看在轨）映射到七个导航分组。旧项目导航只有 3 项（主页 / 发射任务 / 关于），14 张表里有 9 张在界面上根本无入口（只能进 `/admin/`），这是必须修的。

```
首页                 ← 看板：今天该发什么、计划进度
部件库               ← 记录：零部件（燃料罐 / 引擎 / 科学设备 / 其他）
载具                 ← 记录：火箭 · 载荷（含级结构）
发射                 ← 安排 + 记录：发射日志 · 发射日程
计划                 ← 统筹：航天计划 1:n 聚合
在轨                 ← 查看：在役航天器 · 天体
管理后台             ← 逃生门：Django Admin（未在应用中覆盖的 CRUD）
```

### 2.2 全局导航栏结构

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ 🚀 KSP 任务管理   │ 首页 │ 部件库▾ │ 载具▾ │ 发射▾ │ 计划 │ 在轨▾ │      [玩家名 ▾] │
└──────────────────────────────────────────────────────────────────────────────────────┘
                            │           │         │           │
                            │           │         │           └─ 在役航天器 /spacecraft/
                            │           │         │              天体      /bodies/
                            │           │         └─ 发射日志 /flights/
                            │           │            发射日程 /flights/schedule/  ★带角标
                            │           └─ 运载火箭 /carriers/
                            │              有效载荷 /payloads/
                            │              发射场   /sites/
                            └─ 部件总览   /parts/
                               燃料罐     /parts/?part_type=TANK
                               引擎       /parts/?part_type=ENGINE
                               科学设备   /parts/?part_type=SCIENCE
```

| 项 | 实现 |
|---|---|
| 「发射日程」角标 | `{{ pending_flight_count }}`（`FlightLog.objects.filter(state__in=['PLANNED','COUNTDOWN']).count()`），通过**上下文处理器** `launches.context_processors.schedule_badge` 注入全局，避免每个视图都传。`>0` 时显示 `<span class="badge text-bg-warning">` |
| 当前页高亮 | 由每个模板传入 `{% block nav_active %}parts{% endblock %}`，`_navbar.html` 中用 `{% if nav_active == 'parts' %}active{% endif %}` 判断。**不依赖解析 URL**，直白可控 |
| 未登录态 | 右侧显示「登录」链接 → `/accounts/login/?next={{ request.path }}`；已登录显示 `dropdown`（玩家名 / 管理后台 / 退出） |
| 下拉菜单 | Bootstrap 5 `dropdown`，**需要 Bootstrap JS**。故在 `_navbar.html` 中同时输出每个分组的第一个子项作为 `<noscript>` 内的直链，保证极端情况下可达 |

### 2.3 导航项 ↔ 路由名 ↔ URL 对应表

| 分组 | 菜单文字 | 路由名 | URL | 登录 | 备注 |
|---|---|---|---|---|---|
| — | 首页 | `home` | `/` | 否 | 品牌 Logo 与「首页」都指向此 |
| 部件库 | 部件总览 | `part_list` | `/parts/` | 否 | |
| 部件库 | 燃料罐 | `part_list` | `/parts/?part_type=TANK` | 否 | 同一路由带筛选参数 |
| 部件库 | 引擎 | `part_list` | `/parts/?part_type=ENGINE` | 否 | |
| 部件库 | 科学设备 | `part_list` | `/parts/?part_type=SCIENCE` | 否 | |
| 载具 | 运载火箭 | `carrier_list` | `/carriers/` | 否 | |
| 载具 | 有效载荷 | `payload_list` | `/payloads/` | 否 | |
| 载具 | 发射场 | `site_list` | `/sites/` | 否 | 语义上属「地面设施」，暂挂载具组 |
| 发射 | 发射日志 | `flight_list` | `/flights/` | 否 | |
| 发射 | 发射日程 ★ | `flight_schedule` | `/flights/schedule/` | 否 | 带未执行数角标 |
| 计划 | 航天计划 | `program_list` | `/programs/` | 否 | |
| 在轨 | 在役航天器 | `spacecraft_list` | `/spacecraft/` | 否 | 默认 `?is_active=1` |
| 在轨 | 天体 | `body_list` | `/bodies/` | 否 | |
| — | 管理后台 | — | `/admin/` | 是 | Django Admin，`target="_blank"` |
| — | 登录/退出 | — | `/accounts/login/` `/accounts/logout/` | — | Django 内置 |

**`/bodies/` 为何不放「部件库」分组**：天体是**空间坐标与物理常数的来源**（`Site.body`、`Spacecraft.body`、`Program.target_body` 都指向它），与在轨资产同属「空间」语义，故归入「在轨」。

### 2.4 面包屑规范

**格式**：`首页 / <分组> / <当前页>`，最后一段**不可点击**，其余可点击。用 Bootstrap `breadcrumb`。

| 页面 | 面包屑 | 实现要点 |
|---|---|---|
| 列表页 | `首页 / 运载火箭` | 两段 |
| 详情页 | `首页 / 运载火箭 / Davy 2B` | 中间段指向 `carrier_list` |
| 编辑页 | `首页 / 运载火箭 / Davy 2B / 编辑` | **第 3 段回详情**，不是回列表 |
| 新增页 | `首页 / 运载火箭 / 新增` | 无第 3 段链接 |
| 删除确认页 | `首页 / 运载火箭 / Davy 2B / 删除` | 同编辑 |
| 发射日程 | `首页 / 发射 / 发射日程` | 三段 |
| 计划总览 | `首页 / 航天计划 / Duna 探索计划` | |
| 变体血缘树 | `首页 / 运载火箭 / Davy 2B / 变体血缘` | |

**模板实现**：`templates/includes/_breadcrumb.html`，用 `{% include ... with crumbs=crumbs %}` 传入 `crumbs = [{'label':'运载火箭','url':reverse('carrier_list')}, {'label': obj.name}]`（最后一项无 `url`）。**不在模板里硬编码面包屑**，因为编辑/详情的层级关系需要 `reverse()` 保证正确。

### 2.5 与旧导航的对比与改进

旧文件 `templates/includes/_navbar.html`（29 行）：

| 旧做法 | 问题 | 新方案 |
|---|---|---|
| `<nav class="navbar navbar-default">` | Bootstrap **3** 类名，与 `layout.html` 里加载的 Bootstrap **5.1.3 CSS/JS 冲突**（旧项目同时引 BS3 CSS + BS5 JS + 两份 jQuery） | 统一 Bootstrap 5.3，**只引一套** CDN |
| `{% if session.logged_in %}` | 依赖 Flask `session`，Django 模板中不存在 | `{% if user.is_authenticated %}`（Django `AuthenticationMiddleware`） |
| 只有 3 个导航项 | 14 张表有 9 张没有界面入口，玩家必须记 `/admin/` 地址 | 七个分组覆盖全部 14 张表的界面入口 |
| `<a href="/scp">` 硬编码 | URL 改动即断链 | `{% url 'flight_list' %}` 全量命名路由 |
| 无当前页高亮 | 玩家不知自己在哪 | `nav_active` block + `active` 类 + `aria-current="page"` |
| 无角标/提醒 | 「有 3 个任务待发射」完全不可见 | 发射日程角标（2.2） |
| 「控制台（维护中）」 | 死链接 | 改为真实可用的「管理后台」外链 |
| `<span class="sr-only">` | BS3 视觉隐藏类 | BS5 为 `visually-hidden` |
| `navbar-toggle` / `icon-bar` / `data-toggle` | BS3 语法 | BS5 为 `navbar-toggler` / `navbar-toggler-icon` / `data-bs-toggle` |
| 无 `aria-*` | 无障碍缺失 | 折叠按钮加 `aria-controls`/`aria-expanded`，导航加 `aria-label="主导航"` |

## 4. ★ 逐页详细设计

> 通用骨架（所有页面都长这样，后面只描述差异）：

```

│ │     • 🌑 Minmus      半径    60 km   μ 1.766e9   g 0.491      ││
│ │   ▾ 🔴 Duna          半径   320 km   μ 3.014e11  g 2.94       ││

│ │ [ 管理天体（Admin）]                                          │ │
│ └──────────────────────────────────────────────────────────────┘ │

```

**树形缩进的实现（关键）**：Django 模板**不能递归 include 自身以外的任意深度**，但可以：
- 方案 A（采用）：视图侧在 Python 中构建 `tree` 列表，每项带 `depth` 与 `has_children`、`is_expanded`，模板一层 `{% for %}` 循环，用 `style="padding-left: {{ node.depth }}em"` 缩进。**推荐**，简单且可测。
- 方案 B：`{% include 'core/_body_node.html' %}` 自递归（Django 支持，但需要 `only` 传参，调试困难）。

**节点展开**：`<details>` / `<summary>` 原生元素，**不需要 Bootstrap JS**，浏览器原生记忆展开态（`<details open>` 由视图根据是否有感兴趣的子孙决定）。

**表格列 / 节点字段**

| 显示 | 字段 | 格式 |
|---|---|---|
| 名称（缩进） | `name` + `name_en` | 缩进 `depth em`，链接 `body_detail` |
| 半径 | `radius` | `{% widthratio node.radius 1000 1 %} km`（米→千米，1 位小数） |
| μ | `mu` | 科学计数法 `{{ node.mu|floatformat:"-3" }}`，模板侧提供一个 `sci` 过滤器 |
| 表面重力 | `surface_gravity` | `m/s²`，2 位小数 |
| 大气高度 | `atmosphere_height` | `0` 时显示 `无大气` 徽章（`badge text-bg-secondary`） |
| 同步轨道高度 | 由 `mu`+`sidereal_day` 算 | **仅 `body_detail` 显示**，列表页不显示（列表页算 17 条会浪费） |

**空状态**：`Body` 表为空时（未跑 `loaddata fixtures/bodies.json`）：
```
⚠ 天体表还没有数据
请先执行：python manage.py loaddata fixtures/bodies.json
[ 前往管理后台手动添加 ]
```
（这是**唯一允许在界面提示命令行**的地方——它是安装步骤缺失，不是业务为空。）

### 4.6 ★ 火箭详情（`carriers/carrier_detail.html`，`carrier_detail`）—— 最重要的展示页

**使用场景**：玩家来确认「这枚火箭到底能不能把 2.4 t 送到 LEO」；或者想复盘上一次失败是哪一级的问题；或者想看 Davy 2 家族的演化。

**核心设计问题：级序列表「自上而下」还是「自下而上」？**

> **本项目明确规定（基准 4.8，唯一定义）：`stage_order = 1` 表示「第 1 级」= 发射时最先点火、位于最下方的那一级（起飞级）；向上递增，最大序号为最上一级（接近载荷）。**
> **页面渲染：按 `stage_order` 降序自上而下排列，即最大序号（最上一级）在表格顶部、`stage_order = 1` 在底部，与火箭的物理外观一致。**

理由（这是**约定**，不是「玩家习惯」）：
- **与 KSP 游戏一致**：KSP 中空格键触发的第一个分离事件就是「第 1 级」，即最下面最先点火那级。跟随游戏可避免玩家跨系统时的认知转换。
- **与参考项目 `ek` 一致**：`ek.LV(name, family, desc, *stages)` 的 `*stages` **第 1 个参数是最下面那一级**（`ek` 的 `V2 = LV(..., V1, Able, Blue)` 中顺序就是自下而上），与 KSP 语义相同。
- **与 Δv 计算方向一致**：`services.deltav.vehicle_delta_v()` 从 `stage_order = 1` 起**升序**累加（因为计算第 1 级时要把它**上方所有级**的质量计入 $m_0$）。约定统一后，「编号方向」与「计算方向」不再有二义。
- **渲染用降序**：升序计算、降序渲染，两者并不矛盾 —— 渲染要让玩家看到物理形状，计算要遵循质量累加顺序。

> **⚠️ 早期草稿的两种错误写法（已废弃，勿再沿用）**：
> ① 「按 `stage_order` 升序自上而下渲染，`1` 在最上方」—— 与本约定相反，会让「自上而下」的视觉与「自上而下累加」的语义互相抵消；
> ② 「`ek` 的参数第 1 个是最上面那级」—— **误述**。`*stages` 是自下而上（第 1 个是最下面的助推级），因为先抛掉下面的大级才省运力。

**页面做法**：表头明确写「**级序（自上而下，与火箭外观一致）**」，每一行行首显示醒目的 `第 N 级` 徽章（`N` 即 `stage_order`），并常驻一行提示：
`ℹ 本页自上而下显示，底部为第 1 级（最先点火的起飞级）。Δv 从第 1 级起逐级向上累加。`

- **Δv 累加顺序**：`vehicle_delta_v(carrier, payload)` **按 `stage_order` 升序**逐级累加，即先算 `stage_order = 1`。界面的累计条按**渲染顺序（自上而下）**呈现时，数值是「从下往上累积」后再翻转显示 —— **注意这是实现时最易弄反的一处**，须在 `06` 与视图代码中保持一致并加测试。

**为什么用「条长 = 该级 Δv / 总 Δv」而不是「累计值占满整行」**：玩家要一眼比较**哪一级贡献最大**。等比条最直观。累计值放在右列文字里。底部另有一条带刻度的坐标轴（纯 `div` + `border`，无图表库）。

**`dv_rows` 的构造（视图侧，含容错）**

```python
# carriers/views.py · CarrierDetailView.get_context_data
from services import deltav

rows = deltav.vehicle_delta_v(self.object, payload=None)   # 返回 list[StageDeltaV]
total = sum(r.dv for r in rows) if rows else 0.0
dv_rows, cum = [], 0.0
for r in rows:
    cum += r.dv
    dv_rows.append({
        'stage': r.stage,
        'label': f'第 {r.stage.stage_order} 级',
        'dv': r.dv,
        'cumulative': cum,
        'm0': r.m0, 'mf': r.mf,
        'ratio_pct': (r.dv / total * 100) if total else 0,
    })
# 起飞 TWR：body 取「首飞发射场所在天体」，无则 Kerbin
body = (self.object.flights.first().site.body if self.object.flights.exists()
        else Body.objects.filter(code='BODY-KERBIN').first())
twr = deltav.liftoff_twr(self.object, None, body) if body else None
```

**容错与提示（很重要，`services` 返回 `None` 是合同约定的合法情形）**

| 情形 | 界面表现 |
|---|---|
| 火箭无任何级（`stages` 为空） | 级序列表替换为 `_empty_state.html`：`这枚火箭还没有录入级结构 [+ 添加第一级] [编辑火箭]`；摘要条 Δv 显示 `—`，TWR 显示 `—` |
| 某级无引擎 | 该行「引擎」列显示 `⚠ 未指定引擎`（`text-warning`），且该级 Δv **跳过不参与累加**；摘要条下方出现 `alert-warning`：`第 2 级没有引擎，Δv 与 TWR 未计入该级` |
| 某级有引擎但无燃料罐 | 该级 `stage_fuel_mass = 0` → `ln(m0/mf) = 0` → Δv = 0，显示 `0 m/s` 并加 tooltip `该级无燃料，Δv 为 0` |
| `Body.mu` 为空 | TWR 显示 `— μ 缺失`，链接到 `body_detail` 提示补数据 |
| `payload.mass` 未提供 | 载荷列显示 `未指定`，摘要条提示 `未计入载荷质量`（因为 brief 中 `FlightLog.payload` 可空） |

**变体血缘树（内嵌缩略版）**

```
祖先链（is_ancestor 递归 derived_from）        后代子树（variants 递归）
                                              Davy 2
Davy 2  ←  Davy 2A  ←  Davy 2B（当前，加粗边框）  ├─ Davy 2A
                                                │   └─▶ Davy 2B（当前）
                                                └─ Davy 2C
```

**渲染方式**：视图侧 Python 递归构造 `ancestors`（线性链，最多 `max_depth=10` 防环）与 `descendants`（树），模板用**扁平化的 `depth` + `prefix` 字符串**渲染：

```python
def _walk(node, depth=0, seen=None):
    seen = seen or set()
    if node.id in seen or depth > 10:      # 防环 + 防深度爆栈
        return []
    seen = seen | {node.id}
    out = [{'obj': node, 'depth': depth}]
    for v in node.variants.all().order_by('name'):
        out += _walk(v, depth + 1, seen)
    return out
```

模板中缩进用 `{% widthratio node.depth 1 20 %}px` 的 `padding-left`，每个节点前画 `├─`/`└─` 字符（用 `{{ node.prefix }}` 由 Python 生成，模板判断末位元素换 `└─`）。

**空状态**
- 无级：见上表。
- 无变体（`derived_from` 为空且 `variants` 为空）：血缘区块**整块隐藏**，不放空卡片。
- 无发射记录：`这枚火箭还没有发射记录 [ 安排一次发射 ]` → 链接 `flight_create?carrier=<pk>`。

1. **表单顶部汇总**（`form.non_field_errors` + FormSet 的 `non_form_errors`）：

   用 `alert alert-danger` + `<ul>`。**这是旧项目完全没有的能力**（旧项目用 `render_template` 直接丢回表单，无任何错误提示）。
2. **字段级**：`is-invalid` + `<div class="invalid-feedback">{{ field.errors|first }}</div>`。
3. **级行级**：出错的级行加 `border-start border-4 border-danger`，并把该行的错误列在行内（不放折叠区里，否则玩家看不见）。

```python
# launches/views.py · FlightScheduleView.get_context_data
# 1. 只取「尚未执行」的任务
pending = (FlightLog.objects
           .filter(state__in=['PLANNED', 'COUNTDOWN'])
           .select_related('carrier', 'payload', 'site')
           .order_by(F('planned_ut').asc(nulls_last=True), 'code'))

# 2. 按 planned_ut 分组
#    不按固定时间桶分组（玩家 UT 跨度从 0 到几百万，固定桶无意义），
#    而是每个不同的 planned_ut 值一组；null 单独一组放最后。
groups = []
for ut, rows in groupby(pending, key=lambda f: f.planned_ut):
    rows = list(rows)
    groups.append({
        'ut': ut,
        'ut_label': f'{ut:,.0f}' if ut is not None else None,
        'day_label': f'游戏时间 {ut / KSP_DAY:.2f} 天' if ut is not None else None,
        'delta_label': _delta_label(ut),      # 相对 current_max_ut 的差值说明
        'is_overdue': ut is not None and ut < current_ut,
        'flights': rows,
    })

# 3. current_ut = 该玩家存档的「当前游戏时间」
#    v1 取法：已经发射过的任务里 actual_ut 的最大值；无已发射任务则取 0。
#    这是一个刻意的简化（brief 未存「存档当前时间」），页面上要如实说明。
current_ut = (FlightLog.objects
              .filter(actual_ut__isnull=False)
              .aggregate(m=Max('actual_ut'))['m']) or 0.0
```

**三个摘要块的计算（`services/stats.py`）**

```python
# services/stats.py
@dataclass
class ProgramProgress:
    total_members: int
    by_type: dict          # {'CARRIER': 2, 'PAYLOAD': 2, 'FLIGHT': 3, 'SITE': 1, 'SPACECRAFT': 2}
    flight_total: int
    flight_done: int       # state in ('LAUNCHED','FAILED')
    flight_planned: int    # state in ('PLANNED','COUNTDOWN')
    flight_cancelled: int
    success_count: int     # result_code == 0
    fail_count: int        # result_code 非 0 且非空（含 -2/-1/n）
    budget_ratio: float | None    # spent / budget，budget 为 None 时 None
    progress_ratio: float         # flight_done / flight_total，total 为 0 时 0.0
    span_days: float | None       # (end_ut - start_ut) / KSP_DAY
```

| 摘要块 | 公式 | 边界处理 |
|---|---|---|
| **总体进度** | `flight_done / flight_total` | `flight_total == 0` → 进度条显示 `0%` 且文案 `尚无绑定发射`（**不显示 `NaN%`**） |
| **预算执行** | `spent / budget` | `budget` 为 `None` → **不显示进度条**，只显示 `已花费 12 400 √`；`spent > budget` → 进度条 `bg-danger` + `⚠ 超支 2 400 √`；`budget == 0` → 不除零，显示 `预算未设定` |
| **发射完成** | `flight_done / flight_total`，文字 `3/5` | 同时显示计划中 `2` 与已取消 `0` |
| **成功率** | `success_count / flight_done` | `flight_done == 0` → `—` |
| **时间跨度** | `(end_ut - start_ut) / KSP_DAY` | 任一为 `None` → `UT 未定`；`end < start` → `⚠ 结束早于开始`（模型 `clean()` 会拦，此处兜底） |

Django 侧：`ProgramLinkForm` 只暴露 `object_type` + `role_note` + **一个非模型字段 `object_id`**（`ChoiceField`，`choices` 初始为空），在 `clean()` 中按 `object_type` 校验 `object_id` 并填充对应 FK。

```python
# programs/forms.py
TYPE_MODEL = {
    'CARRIER':    (CarrierModel, 'carrier'),
    'PAYLOAD':    (PayloadModel, 'payload'),
    'FLIGHT':     (FlightLog,    'flight'),
    'SITE':       (Site,         'site'),
    'SPACECRAFT': (Spacecraft,   'spacecraft'),
}

class ProgramLinkForm(forms.ModelForm):
    object_id = forms.ChoiceField(label='选择对象', required=True)

    class Meta:
        model = ProgramLink
        fields = ['object_type', 'role_note']

    def __init__(self, *args, program=None, **kwargs):
        super().__init__(*args, **kwargs)
        self.program = program
        self.fields['object_type'].widget.attrs.update({
            'data-link-type': 'true'})          # JS 钩子
        self.fields['object_id'].choices = [('', '请选择…')]
        # 若表单已绑定（含 AJAX 提交的 object_id），或已知 object_type，则填充候选
        ot = (self.data.get('object_type') if self.is_bound
              else self.initial.get('object_type'))
        if ot:
            self.fields['object_id'].choices += self._candidates(ot)

    def _candidates(self, object_type):
        model, _ = TYPE_MODEL[object_type]
        taken = ProgramLink.objects.filter(object_type=object_type) \
                                   .values_list(f'{TYPE_MODEL[object_type][1]}_id', flat=True)
        qs = model.objects.exclude(pk__in=[t for t in taken if t]).order_by('-id')[:500]
        return [(str(o.pk), self._label(object_type, o)) for o in qs]

    def clean(self):
        cleaned = super().clean()
        ot, oid = cleaned.get('object_type'), cleaned.get('object_id')
        if ot and oid:
            model, field = TYPE_MODEL[ot]
            # 再次确认未被占用（防并发/防手工伪造）
            if ProgramLink.objects.filter(object_type=ot, **{f'{field}_id': oid}).exists():
                raise ValidationError('该对象已归属其他计划，请先移除其原计划关系。')
            if not model.objects.filter(pk=oid).exists():
                raise ValidationError('选择的对象不存在。')
            cleaned[field] = model.objects.get(pk=oid)
        return cleaned
```

**AJAX 加载候选**：需要一个小接口。brief 第 6 节未列 `programlink_candidates` 路由，故有两条路：

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（推荐，零新增路由）** | 把**全部候选**随页面一起渲染进 `<template>` 或内联 `<script type="application/json" id="link-candidates">{{ candidates_json|json_script }}</script>`，JS 按 `object_type` 切换 `object_id` 的 `<option>` | 无新增路由、无网络往返、离线可用。代价：候选量大时页面体积大。**v1 单机自用，数据量小（几十到几百），采用 A** |
| B | 新增 `programlink_candidates` 视图（`GET /programs/link/candidates/?object_type=`）返回 JSON | 更"标准"，但要改 `04` 与 brief 第 6 节。**v1 不做**，列为扩展 |

**「与其他值的对照」区块（这是「让玩家知道数字怎么来的」的落地）**

| 对照项 | 计算 | 用途 |
|---|---|---|
| 同步轨道高度 | `orbital.synchronous_sma(body.sidereal_day, body.mu) - body.radius` | 玩家最常问「我这是不是同步轨道」 |
| 大气层高度对照 | `body.atmosphere_height` vs 近拱点高度 | **自动风险预警**：近拱点高度 < 大气高度 + 5 km 时显示 `alert-warning`「近拱点低于大气层，轨道会衰减」 |
| 天体半径对照 | `body.radius` | 解释「半径 vs 高度」的换算 |
| 逃逸速度 | `sqrt(2*mu/r)` | 可选（`06` 未定义则不加） |

**「公式说明」折叠区（`<details>`，无需 Bootstrap JS）**

```
▾ 这些数字是怎么算出来的？
  轨道周期   T = 2π √(a³ / μ)
             = 2π √(700000³ / 3.5316e12)
             = 1 837.4 s
             其中 a = 半长轴 700 000 m，μ = Kerbin 标准重力参数 3.5316e12 m³/s²
  近/远拱点  rp = a(1−e) = 700000 × (1 − 0) = 700 000 m → 表面高度 100 000 m
  周期单位   1 游戏天 = 21 600 s（KSP 太阳日）；本页「天」用此换算。
  数据来源   半长轴与离心率来自本页「轨道六要素」；μ 与半径来自天体 Kerbin。
  [ 查看天体 Kerbin 的常数 → ]
```

> **这一块是「信任设计」**：玩家抄错 `sma` 时会怀疑工具算错。把公式、输入值、结果都摊开，玩家可以自己验算。旧项目完全没有这个概念。

**实现（原生 `fetch`，JS 见 `static/js/orbit_calc.js`）**

```javascript
// static/js/orbit_calc.js（完整可运行）
(function () {
  'use strict';
  const form = document.getElementById('spacecraft-form');
  if (!form) return;
  const url = form.dataset.orbitCalcUrl;        // {% url 'spacecraft_orbit_calc' %}
  const csrf = form.querySelector('[name=csrfmiddlewaretoken]').value;
  const box = document.getElementById('calc-result');
  const cachedInput = form.querySelector('#id_cached_period_sec');
  let timer = null;
  let lastPeriod = null;

  function val(name) {
    const el = form.querySelector('#id_' + name);
    return el && el.value !== '' ? el.value : null;
  }

  function fmtMeters(m) {
    const km = m / 1000;
    return km.toLocaleString('zh-CN', {maximumFractionDigits: 2}) + ' km';
  }

  function render(data) {
    if (!data || data.error) {
      box.innerHTML = '<span class="text-body-secondary">' +
        (data && data.error ? data.error : '需要「天体」+「半长轴」才能计算') + '</span>';
      lastPeriod = null;
      renderDeviation();
      return;
    }
    lastPeriod = data.period_sec;
    const days = data.period_sec / 21600;
    const dayText = days >= 0.01
      ? days.toFixed(4) + ' 游戏天'
      : (data.period_sec / 3600).toFixed(2) + ' 小时';
    box.innerHTML =
      '<div class="row text-center">' +
      row('轨道周期', data.period_sec.toLocaleString('zh-CN', {maximumFractionDigits: 1}) + ' s', dayText) +
      row('近拱点高度', fmtMeters(data.periapsis_alt), '半径 ' + fmtMeters(data.periapsis)) +
      row('远拱点高度', fmtMeters(data.apoapsis_alt), '半径 ' + fmtMeters(data.apoapsis)) +
      (data.speed != null ? row('轨道速度', data.speed.toFixed(0) + ' m/s', '在近拱点') : '') +
      '</div>';
    renderDeviation();
  }

  function row(label, big, sub) {
    return '<div class="col"><div class="small text-body-secondary">' + label + '</div>' +
           '<div class="fs-4 font-monospace fw-semibold">' + big + '</div>' +
           '<div class="small text-body-secondary">' + sub + '</div></div>';
  }

  function renderDeviation() {
    const el = document.getElementById('deviation-hint');
    const cached = cachedInput && cachedInput.value !== '' ? parseFloat(cachedInput.value) : null;
    if (!el) return;
    if (lastPeriod == null || cached == null || isNaN(cached) || cached === 0) {
      el.textContent = '';
      el.className = '';
      return;
    }
    const dev = Math.abs(lastPeriod - cached) / cached * 100;
    el.textContent = '抄录值 ' + cached + ' s vs 计算值 ' + lastPeriod.toFixed(1) +
                     ' s（偏差 ' + dev.toFixed(2) + '%）' + (dev > 1 ? ' ⚠ 超过 1%，请检查半长轴或抄录值' : ' ✓');
    el.className = dev > 1 ? 'form-text text-warning' : 'form-text text-success';
  }

  function refresh() {
    const bodyId = val('body');
    const sma = val('sma');
    if (!bodyId || !sma) { render(null); return; }
    const fd = new FormData();
    fd.append('body_id', bodyId);
    fd.append('sma', sma);
    fd.append('eccentricity', val('eccentricity') || '0');
    fetch(url, {
      method: 'POST',
      headers: {'X-CSRFToken': csrf, 'X-Requested-With': 'XMLHttpRequest'},
      body: fd
    })
      .then(r => r.ok ? r.json() : Promise.reject(new Error('HTTP ' + r.status)))
      .then(render)
      .catch(() => { box.innerHTML = '<span class="text-danger">计算服务暂时不可用，保存后详情页会显示计算值。</span>'; });
  }

  function debounced() { clearTimeout(timer); timer = setTimeout(refresh, 400); }

  ['body', 'sma', 'eccentricity'].forEach(function (n) {
    const el = form.querySelector('#id_' + n);
    if (el) el.addEventListener('input', debounced);
    if (el) el.addEventListener('change', debounced);
  });
  if (cachedInput) cachedInput.addEventListener('input', renderDeviation);
  refresh();   // 页面加载即算一次（编辑已有对象时立即显示）
})();
```

**降级**（Bootstrap JS 不需要；`fetch` 不可用或接口 500 时 → 显示提示文案，**保存仍可用**，详情页会显示服务端算出的值）。这一点很重要：**AJAX 只做「预览」，不是保存的前置条件**。

**校验错误呈现**
| 规则（brief 4.14 `clean()`） | 界面文案 |
|---|---|
| `0 ≤ e < 1` | `离心率必须在 0（含）到 1（不含）之间。若为双曲线/逃逸轨道，请把状态设为「逃逸中」，此时周期不参与计算。` |
| `sma > Body.radius` | `半长轴必须大于天体半径（{{ body.radius }} m）。半长轴是轨道半径，不是相对表面的高度。` |

| 「你是想填高度吗？」提示 | `sma` 输入框下方常驻 `form-text`：`ⓘ 半长轴 = 天体半径 + 表面高度。Kerbin（半径 600 km）+ 100 km 轨道 → 填 700000。` |

**「高度 vs 半径」的混淆是这个页面最大的可用性风险**，必须用常驻提示 + 错误文案双重引导。

## 5. ★ 级表单的动态增删交互设计

> **本节是本项目的交互难点**（brief 7.1、风险 R-03）。内容分为：需求 → 服务端 → 客户端（`stage_formset.js` 完整代码）→ 顺序与 `stage_order` → 两级嵌套 → 降级方案。

### 5.1 需求与模型事实

**玩家的一条火箭有 n 级**，每级含：
- 1 个主引擎（`Stage.engine`，可空）+ 引擎数量（`Stage.engine_count`）
- n 个燃料罐挂载（`StageTank`：`fuel_tank` + `quantity` + `mount_position`）

约束（brief 4.8 / 4.9，必须由服务端强制）：

| 约束 | 层级 |
|---|---|
| `CheckConstraint(owner_type='CARRIER' → carrier 非空 且 payload 空)` | DB |
| `UniqueConstraint(fields=['carrier','stage_order'])` / `['payload','stage_order']` | DB |
| `stage_order >= 1`、`engine_count >= 1` | DB |
| `stage_order` **唯一且连续（1..n 无空洞）** | **`BaseStageFormSet.clean()`**（DB 管不了「连续」） |
| `UniqueConstraint(fields=['stage','fuel_tank','mount_position'])` | DB |
| `quantity >= 1` | DB |

### 5.2 服务端：视图与 FormSet

```python
# stages/formsets.py
from django.forms import inlineformset_factory, BaseInlineFormSet
from django.core.exceptions import ValidationError
from .models import Stage, StageTank

class BaseStageFormSet(BaseInlineFormSet):
    """级 FormSet：校验 stage_order 唯一且连续（1..n 无空洞）。"""

    def clean(self):
        super().clean()
        if any(self.errors):
            # 单行错误已存在，不做整体校验，避免错误信息重复轰炸
            return
        orders = []
        for form in self.forms:
            if not form.cleaned_data:
                continue
            if form.cleaned_data.get('DELETE'):
                continue
            order = form.cleaned_data.get('stage_order')
            if order is not None:
                orders.append(order)
        if not orders:
            # 允许「没有任何级」，brief 未强制 ≥ 1
            return
        orders.sort()
        expected = list(range(1, len(orders) + 1))
        if orders != expected:
            raise ValidationError(
                f'级序号必须从 1 开始连续、无重复。当前为 {orders}，'
                f'应为 {expected}。提交时系统会按页面顺序自动重写级序号 —— '
                f'若你手工改过序号，请清空后重新拖拽排序。',
                code='stage_order_not_contiguous',
            )

    def save_new(self, form, commit=True):
        """新增的级自动填 owner_type / carrier / payload（Brief 5.3 的做法）。"""
        obj = super().save_new(form, commit=False)
        owner_type, owner = self._owner()
        obj.owner_type = owner_type
        if owner_type == 'CARRIER':
            obj.carrier = owner
        else:
            obj.payload = owner
        if commit:
            obj.save()
            self.save_m2m()
        return obj

    def _owner(self):
        # self.instance 是父对象（CarrierModel 或 PayloadModel）
        from carriers.models import CarrierModel
        if isinstance(self.instance, CarrierModel):
            return 'CARRIER', self.instance
        return 'PAYLOAD', self.instance

StageFormSet = inlineformset_factory(
    CarrierModel, Stage,
    formset=BaseStageFormSet,
    fields=['stage_order', 'name', 'engine', 'engine_count', 'is_radial_engine',
            'separation_type', 'decoupler_mass', 'has_fairing',
            'min_throttle_used', 'note'],
    extra=2, can_delete=True,
)
```

```python
class CarrierCreateView(LoginRequiredMixin, CreateView):
    model = CarrierModel
    form_class = CarrierForm
    template_name = 'carriers/carrier_form.html'

    def get_context_data(self, **kwargs):
        ctx = super().get_context_data(**kwargs)
        if self.request.POST:
            ctx['stage_formset'] = StageFormSet(self.request.POST, instance=self.object)
        else:
            ctx['stage_formset'] = StageFormSet(instance=self.object)
        # 供 StageTank 嵌套用（5.5）：每个级行的 tank formset
        ctx['tank_formsets'] = self._build_tank_formsets(ctx['stage_formset'])
        return ctx

    def form_valid(self, form):
        self.object = form.save()
        fs = StageFormSet(self.request.POST, instance=self.object)
        tank_formsets = self._build_tank_formsets(fs, data=self.request.POST)
        if fs.is_valid() and all(tf.is_valid() for tf in tank_formsets):
            self.object = form.save()
            fs.instance = self.object
            instances = fs.save()                 # 保存级
            for tank_fs, stage in zip(tank_formsets, instances):
                tank_fs.instance = stage
                tank_fs.save()
            messages.success(self.request, f'火箭「{self.object.name}」已保存，共 {len(instances)} 级。')
            return redirect(self.object.get_absolute_url())
        return self.render_to_response(
            self.get_context_data(form=form, stage_formset=fs, tank_formsets=tank_formsets))
```

> **`MIN_NUM_FORMS` / `MAX_NUM_FORMS`**：v1 不设上限（玩家自用，KSP 火箭级数不会超过十几个）。若要设，`inlineformset_factory(..., max_num=20)` 只影响**初始显示**数量，**不阻止客户端提交更多**——真正的上限必须由 `BaseStageFormSet.clean()` 检查 `len(orders) > 20` 才可靠。**这一点很容易误解，写进代码注释。**

```javascript
 * 级（Stage）Django FormSet 的动态增删 + 拖拽排序
 *
 * 依赖：无。纯浏览器原生 API（ES2017）。
 *      不需要 jQuery；不需要 Bootstrap JS。
 *      Bootstrap 的 class（btn / card / badge）只是样式，缺了也能工作。
 *
 * 设计要点（对应 docs/05-页面交互设计.md 第 5 节）：
 *  1. 「添加一级」克隆 Django 渲染的 <template id="empty-form">，替换 __prefix__。
 *  2. 「移除」勾选 DELETE 隐藏域 + 隐藏行，绝不从 DOM 删除
 *     （Django FormSet 靠 TOTAL_FORMS 计数，删 DOM 会让索引错乱）。
 *  3. 拖拽排序后按 DOM 顺序重写 stage_order 输入；也支持上移/下移按钮（触屏降级）。
 *  4. 提交前统一重写 stage_order，保证服务端看到的是连续的 1..n。
 * ========================================================================== */
(function () {
  'use strict';

  var PREFIX = 'stages';                       // 与服务端 prefix 一致
  var TOTAL_ID = 'id_' + PREFIX + '-TOTAL_FORMS';
  var INITIAL_ID = 'id_' + PREFIX + '-INITIAL_FORMS';

  var container = document.getElementById(PREFIX + '-container');
  if (!container) return;                       // 本页没有级 FormSet

  var addBtn = document.getElementById('add-stage-btn');
  var tpl = document.getElementById('empty-form');
  var totalInput = document.getElementById(TOTAL_ID);

  /* ---------- 工具函数 ---------------------------------------------------- */

  // 取当前 FormSet 中"可见"的行（含被删除隐藏的？不含——但要保留在 DOM 里）
  function allRows() {
    return Array.prototype.slice.call(
      container.querySelectorAll('.stage-row')
    );
  }

  // 活跃行 = 未勾选 DELETE 的行
  function activeRows() {
    return allRows().filter(function (row) {
      var del = row.querySelector('input[type=checkbox][name$="-DELETE"]');
      return !(del && del.checked);
    });
  }

  function escapeRegExp(s) { return s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&'); }

  // Django 的 empty_form 里所有 name/id 都含 __prefix__，替换成真实索引
  function replacePrefix(html, index) {
    return html.replace(/__prefix__/g, String(index));
  }

  /* ---------- 1. 添加一级 ------------------------------------------------- */

  function addStage() {
    if (!tpl) return;
    var index = parseInt(totalInput.value, 10) || 0;
    var wrapper = document.createElement('div');
    wrapper.innerHTML = replacePrefix(tpl.innerHTML, index).trim();
    // 取 template 里的第一个元素作为行容器
    var row = wrapper.firstElementChild;
    if (!row) return;

    row.classList.add('stage-row');
    row.dataset.formIndex = String(index);
    row.setAttribute('draggable', 'true');

    container.appendChild(row);
    totalInput.value = String(index + 1);      // ★ 关键：TOTAL_FORMS + 1

    // 新行的 stage_order 先给一个占位值，submit 时会按 DOM 顺序重写
    var orderInput = row.querySelector('input[name$="-stage_order"]');
    if (orderInput) orderInput.value = String(activeRows().length);

    bindRowEvents(row);
    renumberVisibleBadges();
    var firstField = row.querySelector('input, select, textarea');
    if (firstField) firstField.focus();
  }

  /* ---------- 2. 移除一级（勾 DELETE + 隐藏）----------------------------- */

  function removeStage(row) {
    // 1) 找 DELETE 复选框：Django 的 can_delete 会渲染
    //    <input type="checkbox" name="stages-3-DELETE" id="id_stages-3-DELETE">
    var del = row.querySelector('input[type=checkbox][name$="-DELETE"]');
    if (del) {
      del.checked = true;
    } else {
      // 2) 没有 DELETE 字段（can_delete=False 或新行）：
      //    新行（未被 INITIAL_FORMS 覆盖的行）可以直接从 DOM 移除，
      //    只需保证 TOTAL_FORMS 不减（Django 允许多余的空白表单被忽略）。
      var idx = parseInt(row.dataset.formIndex, 10);
      var initial = parseInt((document.getElementById(INITIAL_ID) || {}).value, 10) || 0;
      if (idx >= initial) {
        row.remove();
        // ★ TOTAL_FORMS 保持不变：Django 会忽略索引不连续的空表单。
        //   但为了让 renumber 逻辑简单，这里也不回收索引。
        renumberVisibleBadges();
        return;
      }
      // 已存在的行却没有 DELETE 字段 —— 配置问题，退化为隐藏 + 清空必填
      row.querySelectorAll('input, select, textarea').forEach(function (el) {
        if (el.type !== 'hidden') el.disabled = true;
      });
    }
    // 3) 隐藏整行（不删 DOM！）
    row.classList.add('d-none', 'stage-row-deleted');
    // 4) 清掉行内错误样式，避免误显示
    row.querySelectorAll('.is-invalid').forEach(function (el) {
      el.classList.remove('is-invalid');
    });
    renumberVisibleBadges();
  }

  /* ---------- 3. 拖拽排序（原生 HTML5 draggable）------------------------- */

  var dragSrc = null;

  function onDragStart(e) {
    var row = e.target.closest('.stage-row');
    if (!row || row.classList.contains('stage-row-deleted')) return;
    dragSrc = row;
    row.classList.add('opacity-50');
    e.dataTransfer.effectAllowed = 'move';
    // Firefox 必须 setData 才会触发 drag
    try { e.dataTransfer.setData('text/plain', row.dataset.formIndex); } catch (err) {}
  }

  function onDragOver(e) {
    if (!dragSrc) return;
    var row = e.target.closest('.stage-row');
    if (!row || row === dragSrc || row.classList.contains('stage-row-deleted')) return;
    e.preventDefault();
    e.dataTransfer.dropEffect = 'move';
    var rect = row.getBoundingClientRect();
    var after = (e.clientY - rect.top) > rect.height / 2;
    container.insertBefore(dragSrc, after ? row.nextSibling : row);
  }

  function onDragEnd() {
    if (dragSrc) dragSrc.classList.remove('opacity-50');
    dragSrc = null;
    renumberVisibleBadges();
  }

  /* ---------- 4. 上移 / 下移按钮（触屏与键盘降级）------------------------ */

  function move(row, dir) {
    var rows = activeRows();
    var i = rows.indexOf(row);
    if (i < 0) return;
    var j = i + dir;
    if (j < 0 || j >= rows.length) return;
    if (dir < 0) container.insertBefore(row, rows[j]);
    else container.insertBefore(rows[j], row);
    renumberVisibleBadges();
    row.scrollIntoView({block: 'nearest'});
  }

  /* ---------- 5. 视觉上的级号徽章（①②③…）------------------------------- */

  var CIRCLED = ['①','②','③','④','⑤','⑥','⑦','⑧','⑨','⑩',
                 '⑪','⑫','⑬','⑭','⑮','⑯','⑰','⑱','⑲','⑳'];

  function renumberVisibleBadges() {
    activeRows().forEach(function (row, i) {
      var badge = row.querySelector('.stage-order-badge');
      if (badge) badge.textContent = CIRCLED[i] || ('#' + (i + 1));
      var hint = row.querySelector('.stage-order-hint');
      if (hint) hint.textContent = '序 ' + (i + 1);
    });
  }

  /* ---------- 6. 提交前：按 DOM 顺序重写 stage_order ---------------------- */

  function rewriteStageOrder() {
    var rows = activeRows();
    rows.forEach(function (row, i) {
      var input = row.querySelector('input[name$="-stage_order"]');
      if (input) input.value = String(i + 1);     // 1..n 连续
    });
    // TOTAL_FORMS 必须 >= 所有出现的索引 + 1。
    // 正常增删下 totalInput.value 已经正确；这里做一次防御性修正。
    var maxIdx = -1;
    allRows().forEach(function (r) {
      var n = parseInt(r.dataset.formIndex, 10);
      if (!isNaN(n) && n > maxIdx) maxIdx = n;
    });
    if (maxIdx + 1 > (parseInt(totalInput.value, 10) || 0)) {
      totalInput.value = String(maxIdx + 1);
    }
  }

  /* ---------- 7. 行内事件绑定 -------------------------------------------- */

  function bindRowEvents(row) {
    var removeBtn = row.querySelector('.remove-stage-btn');
    if (removeBtn) {
      removeBtn.addEventListener('click', function (e) {
        e.preventDefault();
        removeStage(row);
      });
    }
    var upBtn = row.querySelector('.move-up-btn');
    var downBtn = row.querySelector('.move-down-btn');
    if (upBtn) upBtn.addEventListener('click', function (e) { e.preventDefault(); move(row, -1); });
    if (downBtn) downBtn.addEventListener('click', function (e) { e.preventDefault(); move(row, 1); });

    row.addEventListener('dragstart', onDragStart);
    row.addEventListener('dragover', onDragOver);
    row.addEventListener('dragend', onDragEnd);
    row.addEventListener('drop', function (e) { e.preventDefault(); });

    // 可折叠的「燃料罐」子区（如果实现了嵌套，见 5.5）
    var toggle = row.querySelector('.toggle-tanks-btn');
    if (toggle) {
      toggle.addEventListener('click', function (e) {
        e.preventDefault();
        var body = row.querySelector('.tanks-body');
        if (body) body.classList.toggle('d-none');
        toggle.setAttribute('aria-expanded',
          String(!(body && body.classList.contains('d-none'))));
      });
    }
  }

  /* ---------- 8. 初始化与表单提交拦截 ------------------------------------ */

  container.addEventListener('dragover', function (e) { if (dragSrc) e.preventDefault(); });

  if (addBtn) addBtn.addEventListener('click', function (e) { e.preventDefault(); addStage(); });

  allRows().forEach(function (row) {
    row.setAttribute('draggable', 'true');
    if (!row.dataset.formIndex) {
      // 服务端渲染的行：从 name 里解析索引
      var probe = row.querySelector('input[name], select[name], textarea[name]');
      if (probe) {
        var m = probe.name.match(new RegExp('^' + escapeRegExp(PREFIX) + '-(\\d+)-'));
        if (m) row.dataset.formIndex = m[1];
      }
    }
    bindRowEvents(row);
  });
  renumberVisibleBadges();

  var form = container.closest('form');
  if (form) {
    form.addEventListener('submit', function () {
      rewriteStageOrder();
      // 提交按钮防连点（避免重复 POST）
      form.querySelectorAll('button[type=submit]').forEach(function (b) {
        b.disabled = true;
        setTimeout(function () { b.disabled = false; }, 3000);
      });
    });
  }

  // 暴露给调试与（可选的）AJAX 调用
  window.StageFormSet = {
    add: addStage,
    remove: removeStage,
    rows: activeRows,
    rewriteOrder: rewriteStageOrder
  };
})();
```

### 5.4 `TOTAL_FORMS` / `INITIAL_FORMS` 的正确更新方式（最容易写错的地方）

**Django FormSet 的协议**：

| 管理字段 | 含义 | 谁负责维护 |
|---|---|---|
| `<prefix>-TOTAL_FORMS` | 本次提交里**表单的总数量**（包含新增与已有，不区分是否 DELETE） | **客户端**（每次克隆/移除后必须更新） |
| `<prefix>-INITIAL_FORMS` | 从数据库加载时**已存在的表单数量** | **客户端不动**（服务端渲染时写死；它决定「索引 ≥ INITIAL_FORMS 的表单是新增」） |
| `<prefix>-MIN_NUM_FORMS` / `MAX_NUM_FORMS` | 校验用边界 | 客户端不动 |

**规则表（务必照做）**

| 操作 | `TOTAL_FORMS` | `INITIAL_FORMS` | DOM |
|---|---|---|---|
| 页面初始化（服务端渲染 3 个已有级 + 2 个空行） | `5` | `3` | 5 行 |
| 点「+ 添加一级」 | `5 → 6`（**+1**） | `3`（不变） | 追加第 6 行（索引 5） |
| 点某行「移除」，该行**是已有的**（索引 < `INITIAL_FORMS`） | **不变**（仍 6） | 不变 | 行**隐藏**，其 `DELETE` 勾选 |
| 点某行「移除」，该行**是新增的**（索引 ≥ `INITIAL_FORMS`） | **可以不变**（推荐不变，最稳） | 不变 | 行可直接移除 |
| 提交前 | 保证 `TOTAL_FORMS ≥ max(索引) + 1` | 不变 | 活跃行 `stage_order` 重写为 1..n |

**为什么 `TOTAL_FORMS` 不能因为「移除」而减 1**：
- Django 会遍历 `range(TOTAL_FORMS)`，对每个索引 `i` 用 `prefix-i-field` 去 `POST` 里取值。索引 3 被移除后若把 `TOTAL_FORMS` 从 5 改成 4，则索引 4 的表单**被静默丢弃**，而索引 3 若原来没有 `DELETE` 字段就变成不存在——但**数据库里那条记录不会被删**，玩家会以为删了其实没删。**这是 Django FormSet 最经典的静默数据错误。**
- 正确做法：**`TOTAL_FORMS` 只增不减**（在本项目的交互里，除了「新增行直接删除 DOM」这一种情形，`TOTAL_FORMS` 严格只增）。被隐藏的已存在行通过 `DELETE=on` 让 Django 真正删除记录。

**为什么「不能真的从 DOM 删除」已存在的行**：
- 删掉 DOM 后，该行的隐藏管理字段（`id`、`DELETE`）也一起消失，Django 完全看不到它 → **记录不会被删除**，而且若 `TOTAL_FORMS` 被人为改小，后面的索引会错位，导致**把 A 级的字段值写到 B 级上**（这是最坏的结果：静默串行）。
- 因此 `removeStage()` 只做：勾 `DELETE` + `classList.add('d-none')`。

**代码里的三处关键点（对照上面的 JS）**
```javascript
// ① 添加：TOTAL_FORMS 加 1
totalInput.value = String(index + 1);

// ② 移除已有行：不动 TOTAL_FORMS，只勾 DELETE + 隐藏
del.checked = true;
row.classList.add('d-none', 'stage-row-deleted');

// ③ 提交前：防御性保证 TOTAL_FORMS 覆盖所有索引
if (maxIdx + 1 > (parseInt(totalInput.value, 10) || 0)) {
  totalInput.value = String(maxIdx + 1);
}
```

**服务端必须能容忍「不连续索引」**：Django 的 `BaseFormSet` 天然容忍（`range(TOTAL_FORMS)` 里取不到字段的表单就是空表单，会被跳过）。**不要写自定义逻辑去「压缩索引」**，那会引入 bug。

### 5.5 顺序即 `stage_order`：为什么顺序重要，以及怎么落库

**为什么顺序重要（这是 `ek` 教的关键）**

`ek` 项目里，一枚火箭的级序列是**函数调用的参数顺序**：

```python
# ek.py（示意）
LV("Davy 2", Davy2Family, "描述",
   Stage(engine_lv909, 1),     # stages[0]
   Stage(engine_lvt45, 1),     # stages[1]
   Stage(engine_rt10,  4))     # stages[2]
```

参数顺序**天然携带了「哪一级在上面、哪一级先点火」的信息**，且不可能有两个 `stages[0]`。

到了关系库，**`INSERT` 的顺序不构成语义**：`Stage` 表里三条记录的物理存储顺序与火箭的级顺序无关，`SELECT * FROM stages_stage WHERE carrier_id=1` 不保证任何顺序。因此在 `ek` 里免费得到的「级位置」，在关系库里**必须显式落成一列** —— 这就是 `Stage.stage_order`（brief 4.8 设计说明的原话）。

**顺序的语义后果**（不是装饰性的）：

| 用到顺序的地方 | 后果 |
|---|---|
| Δv 逐级累加（`services/deltav.vehicle_delta_v`） | 累加顺序错了，`m0`（上方所有级质量）就算错，**整枚火箭的 Δv 全错** |
| 起飞 TWR | 取的是 `stage_order` 最小那一级的引擎推力与数量 |
| 详情页级序列表 | 玩家按此对照 KSP 里的火箭外观 |
| `Stage.engine_count` 的解释 | `× 4` 只对助推级有意义，写在错级上就是脏数据 |

**提交时怎么重写（双保险）**

| 时机 | 动作 | 代码位置 |
|---|---|---|
| 提交前（同步，主路径） | 按 DOM 顺序把活跃行的 `stage_order` 输入重写为 1..n | `stage_formset.js` 的 `rewriteStageOrder()`，绑在 `form.submit` |
| 保存后（可选，异步） | 若启用了 `stage_reorder` AJAX，提交后按 id 列表再排一次 | 见下面的可选增强 |
| 服务端（终审） | `BaseStageFormSet.clean()` 校验 1..n 连续无空洞 | `stages/formsets.py` |

**可选增强：`stage_reorder` AJAX**

当表单已存在（编辑模式）、玩家只改了顺序、不想重填整个表单时，可用拖拽结束 → 调 `POST /stages/reorder/`：

```javascript
// 可选增强：拖拽结束即持久化顺序（不依赖表单提交）
// 只在「编辑已存在的火箭」时启用：所有活跃行都必须有 id。
function persistOrder() {
  var ids = activeRows()
    .map(function (r) {
      var idInput = r.querySelector('input[name$="-id"]');
      return idInput && idInput.value ? parseInt(idInput.value, 10) : null;
    })
    .filter(function (v) { return v !== null; });
  if (ids.length !== activeRows().length) return;   // 有新增行，无法局部重排，等表单提交

  var fd = new FormData();
  fd.append('owner_type', OWNER_TYPE);              // 'CARRIER' | 'PAYLOAD'
  fd.append('owner_id', OWNER_ID);
  ids.forEach(function (id) { fd.append('order[]', String(id)); });

  fetch(REORDER_URL, {          // {% url 'stage_reorder' %}
    method: 'POST',
    headers: {'X-CSRFToken': CSRF, 'X-Requested-With': 'XMLHttpRequest'},
    body: fd
  }).then(function (r) { return r.ok ? r.json() : Promise.reject(r.status); })
    .then(function (data) {
      if (data && data.ok) showToast('级序已保存', 'success');
    })
    .catch(function () {
      showToast('级序保存失败，提交表单时会一并保存', 'warning');
    });
}
// 在 onDragEnd 里加 400ms debounce 后调用 persistOrder()（仅当页面有 data-reorder-url）
```

> **注意**：`stage_reorder` 的请求体格式（`order[]` vs `ids`）以 `04-接口与路由设计.md` 为准，本文给出的是 `order[]` 数组形式，实现时如 `04` 不同则以 `04` 为准并回改本文。

**服务端 `StageReorderView` 的必要校验**（写进 `08` 任务）：
```python
# stages/views.py
class StageReorderView(LoginRequiredMixin, View):
    def post(self, request):
        owner_type = request.POST.get('owner_type')
        owner_id = request.POST.get('owner_id')
        ids = request.POST.getlist('order[]')
        # ★ 校验：所有 id 必须属于同一个 owner，否则玩家可以重排别人的级
        qs = Stage.objects.filter(owner_type=owner_type, **{owner_type.lower(): owner_id})
        if set(map(int, ids)) != set(qs.values_list('id', flat=True)):
            return JsonResponse({'ok': False, 'error': '级列表与服务器不一致，请刷新页面后重试。'},
                                status=400)
        with transaction.atomic():
            for i, sid in enumerate(ids, start=1):
                # 先腾空 stage_order 避免 UniqueConstraint 冲突：两步走
                Stage.objects.filter(pk=sid).update(stage_order=-i)
            for i, sid in enumerate(ids, start=1):
                Stage.objects.filter(pk=sid).update(stage_order=i)
        return JsonResponse({'ok': True})
```
> **`UniqueConstraint(['carrier','stage_order'])` 与批量重排的冲突**：把 `[1,2,3]` 改成 `[3,2,1]` 时，中间状态会撞唯一约束。**必须两步走（先置负数再置正数）或先全部 `stage_order += 1000`**。这是必须写入 `08` 的实现细节，否则测试时会遇到莫名其妙的 `IntegrityError`。

### 5.6 两级嵌套：`Stage` 内的 `StageTank` FormSet

**目标**：在火箭编辑页的每个级行内部，直接管理该级的燃料罐。

**方案：前缀嵌套（Django FormSet 的标准姿势）**

Django 的 FormSet 前缀是可组合的。把「级的 FormSet」前缀设为 `stages`，则第 `i` 级的「燃料罐 FormSet」前缀设为 `stages-{i}-tanks`：

```
stages-TOTAL_FORMS = 3
stages-0-stage_order = 1
stages-0-tanks-TOTAL_FORMS = 2          ← 第 0 级的燃料罐 FormSet
stages-0-tanks-0-fuel_tank = 5
stages-0-tanks-0-quantity = 2
stages-0-tanks-0-mount_position = INLINE
stages-0-tanks-1-fuel_tank = 3
stages-0-tanks-1-quantity = 1
stages-1-tanks-TOTAL_FORMS = 0
```

**服务端**

```python
# stages/formsets.py
StageTankFormSet = inlineformset_factory(
    Stage, StageTank,
    fields=['fuel_tank', 'quantity', 'mount_position', 'note'],
    extra=1, can_delete=True,
)

def build_tank_formsets(stage_formset, data=None):
    """
    为 stage_formset 的每一行构造一个 StageTankFormSet。
    返回 list，索引与 stage_formset.forms 一一对应。
    """
    result = []
    for i, form in enumerate(stage_formset.forms):
        prefix = f'{stage_formset.prefix}-{i}-tanks'
        instance = form.instance if form.instance.pk else Stage()   # 新增级用空 Stage 兜底
        if data is not None:
            result.append(StageTankFormSet(data, instance=instance, prefix=prefix))
        else:
            result.append(StageTankFormSet(instance=instance, prefix=prefix))
    return result
```

**模板（关键片段）**

```html
{# carriers/carrier_form.html #}
<form method="post" id="carrier-form">
  {% csrf_token %}
  {{ stage_formset.management_form }}     {# stages-TOTAL_FORMS 等 #}

  <div id="stages-container">
```

**客户端的额外工作（嵌套的复杂度就在这里）**

| 问题 | 解法 |
|---|---|
| 新克隆的级行，其内部 tank 行的前缀含**旧索引** | 克隆后要**二次替换**：先 `__prefix__ → i`（级），再对该级内 tank 的 `stages-{oldIdx}-tanks` 前缀整体替换为 `stages-{i}-tanks` |
| tank 的 `empty_form` 也要按当前级索引生成前缀 | 用 `<template id="empty-tank-form">` 的 HTML，把 `stages-__prefix__-tanks-__prefix__` 中的**两处** `__prefix__` 分别替换 |
| 移除级行后，其 tank 的 `DELETE` 也要勾上 | `removeStage()` 里递归 `row.querySelectorAll('input[name$="-DELETE"]').forEach(el => el.checked = true)` —— **这是嵌套方案中最容易漏的一步**，漏了会导致「删了级，燃料罐还挂在幽灵 Stage 上」或 FK 报错 |
| 提交前的 `stage_order` 重写不受嵌套影响 | 只重写 `name$="-stage_order"` 且**限定在级行内**（`row.querySelector('input[name$="-stage_order"]')` 会同时匹配 tank 行里的字段吗？不会，tank 没有 `stage_order` 字段，安全） |

**`_stage_row.html` 与 `_tank_row.html` 两个 include 片段是必须的**：客户端克隆需要服务端渲染好的 HTML 骨架，这样 `<select>` 的选项（引擎、燃料罐列表）**不需要 JS 再取一次数据**——**这是「无构建链」方案最实际的省力点**。

### 5.7 降级方案

**触发条件（任一满足即降级）**

| # | 触发条件 | 判断时机 |
|---|---|---|
| T1 | 两级嵌套的 `_stage_row.html` 模板中出现超过 **3 处** `stages-__prefix__-tanks-__prefix__` 的双层前缀替换逻辑，且自测出现前缀错乱 | P2 阶段第 2 天 |
| T2 | 新增级 → 展开燃料罐 → 添加燃料罐 → 保存 的端到端测试**在 2 小时内未能通过** | P2 阶段 |
| T3 | `TOTAL_FORMS` 双层维护导致出现「保存成功但燃料罐丢失/串行」的难以复现问题 | P2 阶段 |
| T4 | 该功能的实现工时超过 **1.5 人日** | P2 阶段末 |

**降级后的形态**

| 项 | 完整版 | 降级版 |
|---|---|---|
| 火箭编辑页管理范围 | 级 + 引擎 + 引擎数量 + **每级的燃料罐** | **仅级 + 引擎 + 引擎数量 + 级序号** |
| 燃料罐管理位置 | 火箭编辑页的级行内（嵌套 FormSet） | **级独立编辑页 `stage_update`**（`StageTank` FormSet，单层，无嵌套） |
| 火箭编辑页的级行 | 有 `[燃料罐 ▾]` 展开按钮 | 改为 `[编辑本级燃料罐 →]` 链接 → `stage_update` |
| 火箭详情页 | 燃料罐列直接显示 | 不变（只读展示，与是否嵌套无关） |
| 火箭编辑页额外提示 | — | 保存成功后 `messages.info`：`提示：每级的燃料罐请在「编辑此级」页面维护（共 5 级的燃料罐待确认）。` |
| 级序拖拽排序 | 保留 | **保留**（这是核心交互，不在降级范围） |
| Δv 计算 | 不受影响（读的是 `StageTank` 表，与录入路径无关） | 不受影响 |

**验收标准的差异（必须写进 `08`）**

| 验收项 | 完整版 | 降级版 |
|---|---|---|
| 端到端 | 在火箭编辑页一次提交完成「3 级 + 每级 2 种燃料罐」的创建，刷新后详情页显示正确 Δv | 分两步：① 火箭编辑页建 3 级 ② 逐级进 `stage_update` 加燃料罐；③ 详情页显示正确 Δv |
| 交互测试 | 拖拽第 1 级到第 3 位 → 提交 → 详情页级序与 Δv 累加顺序同步变化 | 同 |
| 回归测试 | 删除中间一级 → 提交 → 剩余级 `stage_order` 为 1..n-1 连续 | 同（**降级版这一步更容易通过**，因为不涉及嵌套 DELETE） |
| 工时 | 预估 1.5–2 人日 | 预估 0.5 人日（`stage_update` 页本来就要做） |

> **建议**：**先实现降级版跑通全链路（P2 前半），再尝试嵌套（P2 后半）**。因为 `stage_update` 页无论是否降级都必须存在（详情页的 `[编辑此级]` 需要它），把它作为燃料罐的保底入口，风险为零。这符合 brief R-03「待验证 + 有降级方案」的定位。

### 6.1 状态机可视化

**非法状态转换的防护**（`flight_launch` 视图必须做）：
```python
# launches/views.py
class FlightLaunchView(LoginRequiredMixin, View):
    def post(self, request, pk):
        with transaction.atomic():
            flight = get_object_or_404(FlightLog.objects.select_for_update(), pk=pk)
            if flight.state not in ('PLANNED', 'COUNTDOWN'):
                messages.error(request,
                    f'无法执行 {flight.code}：当前状态为「{flight.get_state_display()}」，'
                    f'只有「计划中」或「发射准备」的任务可以执行发射。')
                return redirect('flight_schedule')
            # actual_ut：表单传来则用，否则用「已知最大 UT + 1」作为缺省
            actual = request.POST.get('actual_ut') or None
            if actual is None:
                current = (FlightLog.objects.filter(actual_ut__isnull=False)
                           .aggregate(m=Max('actual_ut'))['m'] or 0.0)
                actual = current
            flight.state = 'FAILED' if request.POST.get('result_code') not in (None, '', '0') else 'LAUNCHED'
            flight.actual_ut = float(actual)
            rc = request.POST.get('result_code')
            flight.result_code = int(rc) if rc not in (None, '') else 0
            flight.full_clean(exclude=['code', 'name', 'carrier', 'site'])  # 触发 clean() 规则
            flight.save()
        messages.success(request, f'{flight.code}「{flight.name}」已记录为'
                                  f'{"发射失败" if flight.state == "FAILED" else "已发射"}。')
        return redirect('flight_schedule')
```
> **`result_code != 0` 时 `state` 应设为 `FAILED`** —— brief 未显式规定这个联动，但语义上「台架中止/任务失败/某级失效」都属于失败。**这一点需要在 `04` 或 `06` 中确认并回写 brief**；本文按「`result_code` 非 0 → `FAILED`」实现，并在界面上让玩家能手动改回。

### 6.3 `result_code` 的选择交互（语义编码，不能自由输入）

**`result_code` 的语义（brief 4.11）**

| 值 | 含义 | 玩家的表述 |
|---|---|---|
| `NULL` | 尚未执行 | 「还没发」 |
| `-2` | 台架中止（T-0 前失败，发射夹未释放） | 「点火前就中止了」 |
| `-1` | 任务失败（各级工作正常，但设计缺陷导致任务失败） | 「火箭没问题，是设计/操作问题」 |
| `0` | 成功 | 「成功了」 |
| `>0` | 第 n 级失效 | 「第 3 级炸了」 |

**禁止自由输入的原因**：`-1` / `-2` / `n` 这三个值玩家无法凭直觉写出，且自由输入会产生「第 3 级失败」「3级」「-3」等不可统计的脏值。**必须是选择器**。

```javascript
// common.js 片段：结果选择器
(function () {
  var radios = document.querySelectorAll('input[name=result_choice]');
  if (!radios.length) return;
  var hidden = document.getElementById('id_result_code');
  var failDetail = document.getElementById('fail-detail');
  var stageSel = document.getElementById('fail-stage-select');

  function sync() {
    var picked = document.querySelector('input[name=result_choice]:checked');
    if (!picked) return;
    var v = picked.value;
    if (v === 'fail') {
      failDetail.classList.remove('d-none');
      hidden.value = stageSel.value;             // '-1' 或 'n'
    } else {
      failDetail.classList.add('d-none');
      hidden.value = v;                          // '0' 或 '-2'
    }
  }

  radios.forEach(function (r) { r.addEventListener('change', sync); });
  if (stageSel) stageSel.addEventListener('change', sync);

  // 编辑已有任务时，按 result_code 反推选中的单选
  var current = hidden.value;
  if (current !== '' && current !== null) {
    if (current === '0')      document.getElementById('rc-success').checked = true;
    else if (current === '-2') document.getElementById('rc-pad').checked = true;
    else {
      document.getElementById('rc-fail').checked = true;
      if (stageSel) stageSel.value = current;    // '-1' 或 'n'
    }
  }
  sync();
})();
```

|---|---|
| 火箭没有级（`stages` 为空） | `stage_options` 为空 → 下拉里只有「非级次原因（-1）」，并在下方提示 `这枚火箭还没有录入级结构，无法按级次记录失效原因 [ 去补充级结构 ]` |

## 7. 计算结果的展示规范

> 依赖：`services/orbital.py`、`services/deltav.py`、`services/stats.py`（brief 8.7）。所有计算值均由**视图层**调用服务后传入模板；**模板中不做计算**（模板里的 `widthratio`/`floatformat` 只做格式化，不做公式）。

### 7.1 Δv — m/s，大字突出

| 场景 | 位置 | 呈现 |
|---|---|---|
| 火箭详情摘要条 | 页面顶部 | `<span class="fs-3 fw-bold font-monospace">6 420</span> <small class="text-body-secondary">m/s</small>` |
| 逐级 Δv 条 | 级序列表下方 | 每行右侧 `1 850 m/s`，`font-monospace` |
| 发射日程卡片 | 卡片右侧（可选） | 小徽章 `⚡ 6 420 m/s` |
| 计划总览的火箭行 | 表格列 | 普通字号 + 等宽数字 |

**格式规范**：
- 千位分隔：Django 模板用 `{{ dv|floatformat:0 }}` 后由 `django.contrib.humanize` 的 `intcomma` 加分隔（`{% load humanize %}{{ dv|floatformat:0|intcomma }}`）→ `6 420`（`intcomma` 默认用 `,`；若要空格需配置 `USE_THOUSAND_SEPARATOR` + `THOUSAND_SEPARATOR=' '`）。**约定：项目统一用空格作千位分隔**（中文技术文档习惯），配置 `settings/base.py`：
  ```python
  USE_THOUSAND_SEPARATOR = True
  THOUSAND_SEPARATOR = '\u00a0'      # 不换行空格，防止数字在行尾断开
  NUMBER_GROUPING = 3
  ```
  > **⚠ 副作用**：开启 `USE_THOUSAND_SEPARATOR` 会影响**所有**数字渲染，包括 `<input value="...">` 里的值和 `UT` 这种整数。**UT 绝对不能带分隔符**（`428 900` 放进 `type="number"` 输入框会变成 `NaN`）。因此**不全局开启**，改为定义模板过滤器 `core/templatetags/ksp.py::spaced_int`：
  ```python
  @register.filter
  def spaced_int(value):
      """6420 → '6 420'；None → '—'。仅用于展示，不用于 input value。"""
      if value is None:
          return '—'
      try:
          return f'{int(round(float(value))):,}'.replace(',', '\u00a0')
      except (TypeError, ValueError):
          return '—'
  ```
- 单位与数值之间一个空格：`6 420 m/s`，不是 `6420m/s`。
- 数值为空（无法计算）：显示 `—`（em dash），**不显示 `0` 或 `NaN`**。`0 m/s` 与「算不出」是两回事。

### 7.2 推重比 — 2 位小数 + 阈值颜色（brief 8.2）

| 阈值 | 判定 | 展示 | Bootstrap 类 | 附加文案 |
|---|---|---|---|---|
| `< 1.2` | 推重比不足 | `1.08` | `text-danger` | `✗ 推重比不足，无法起飞` |
| `1.2 ≤ x ≤ 1.7` | **合理区间** | `1.42` | `text-success` | `✓ 合理` |
| `1.7 < x ≤ 2.5` | 偏高 | `2.10` | `text-warning` | `⚠ 偏高，重力损失增加` |
| `> 2.5` | 过推 | `3.20` | `text-danger` | `⚠ 过推，气动损失大` |
| 无法计算（无 `mu` / 无起飞级引擎） | — | `—` | `text-body-secondary` | `缺少天体 μ 或无起飞级引擎` |

**实现**：视图侧算好 `twr` 与 `twr_class`、`twr_hint` 三个值传模板（**判定逻辑不写在模板里**，因为它是 brief 8.2 的业务规则，需要单测）：

```python
# services/deltav.py
def twr_assessment(twr: float | None) -> tuple[str, str, str]:
    """返回 (显示值, Bootstrap 文本类, 提示文案)。阈值见 brief 8.2。"""
    if twr is None:
        return '—', 'text-body-secondary', '缺少天体 μ 或无起飞级引擎'
    v = f'{twr:.2f}'
    if twr < 1.2:
        return v, 'text-danger', '✗ 推重比不足，无法起飞'
    if twr <= 1.7:
        return v, 'text-success', '✓ 合理'
    if twr <= 2.5:
        return v, 'text-warning', '⚠ 偏高，重力损失增加'
    return v, 'text-danger', '⚠ 过推，气动损失大'
```

**tooltip 补充信息**（hover TWR 数字）：
```
推力 200 kN × 1 = 200 kN
起飞质量 24.8 t → 重量 24.8 × 9.81 = 243.3 kN
TWR = 200 / 243.3 = 0.82 ... 
（正确示例）TWR = 345.6 / 243.3 = 1.42
g_local = μ / r² = 3.5316e12 / 600000² = 9.81 m/s²
```

### 7.3 轨道周期 — 秒 + 游戏天，并对照抄录值（brief 8.3）

**双单位展示（强制）**

```
轨道周期
1 837.4 s                          ← 主显示，等宽，fs-4
0.0851 游戏天                       ← 副显示，小字
```
- 秒：1 位小数。
- 游戏天：`period / 21600`，4 位小数。
- **`< 0.01 天` 时改用小时**：`≈ 0.51 小时` 比 `0.0014 天` 好读。阈值与格式：
  ```python
  def format_period(period_sec):
      if period_sec is None:
          return '—', '—'
      sec = f'{period_sec:,.1f} s'
      days = period_sec / KSP_DAY
      sub = f'{days:.4f} 游戏天' if days >= 0.01 else f'≈ {period_sec/3600:.2f} 小时'
      return sec, sub
  ```
- **`ESCAPING` / `e ≥ 1` 的航天器不显示周期**，显示 `—` + tooltip `逃逸轨道不适用周期公式（v1 只处理椭圆轨道）`。

**「计算值 vs 抄录快照值」对照（brief 8.3，偏差 > 1% 提示）**

| 情形 | 展示 |
|---|---|
| `cached_period_sec` 为空 | 只显示计算值，**不显示对照行**（不写「未抄录」，避免噪音） |
| 偏差 ≤ 1% | `<span class="text-success">抄录 1 850 s · 偏差 0.67% ✓</span>` |
| 偏差 > 1% | `<span class="text-warning">⚠ 抄录 1 850 s vs 计算 1 837.4 s，偏差 0.68% 超过 1%</span>` + tooltip：`请检查「半长轴」是否录入有误，或抄录值来自不同版本/模组。计算值以 sma 与天体 μ 为准。` |
| `sma` 为空但有抄录值 | 主显示 `—`，对照行 `抄录 1 850 s`，加 `⚠ 缺少半长轴，无法验证抄录值` |
| `mu` 为空（天体数据不全） | 主显示 `—` + `⚠ 天体 {{ body.name }} 缺少 μ，无法计算周期`，链接到 `body_detail` |

**偏差计算的浮点注意**：`cached == 0` 时不做除法（视为无抄录值，显示 `抄录 0 s（无效值）`）。

### 7.5 公式展示 — tooltip 或折叠区

**原则**：**列表页不展示公式**（信息密度优先）；**详情页提供**（让玩家知道数字怎么来的）。

|---|---|---|

### 9.2 加载态

**本项目的加载形态**：单机 + SQLite，页面请求通常在 50ms 内完成。**不做骨架屏、不做 spinner**（过度设计）。只有三处真正异步的地方需要加载态：

| 场景 | 交互 | 加载表现 |
|---|---|---|
| 航天器表单的 AJAX 周期计算（`orbit_calc`） | 输入变化 debounce 400ms 后 `fetch` | 预览区加 `loading-text` 类 → CSS 伪元素显示「 计算中…」；**不阻塞输入，不遮罩表单** |
| 级序 AJAX 重排（`stage_reorder`） | 拖拽结束 debounce 400ms | 拖拽手柄旁显示小字「保存级序…」，成功后 `toast` 或静默（推荐静默 + 400ms 后显示「✓」） |
| 表单提交（所有 POST） | 原生表单提交 | 点击后 `button.disabled = true` + 文案改「保存中…」（`common.js` 统一处理，3 秒后自动恢复防卡死） |

**统一实现（`common.js` 片段）**

```javascript
// 提交按钮防连点：所有 <form> 的 submit 按钮
document.addEventListener('submit', function (e) {
  var form = e.target;
  if (!(form instanceof HTMLFormElement)) return;
  form.querySelectorAll('button[type=submit], input[type=submit]').forEach(function (b) {
    setTimeout(function () { b.disabled = true; }, 0);   // 延后一拍，保证提交已发出
    setTimeout(function () { b.disabled = false; }, 8000); // 兜底恢复
  });
}, true);
```

**加载态的边界**：AJAX 请求超过 **5 秒**未返回 → 显示「请求超时，请刷新页面重试」（`AbortController` + `setTimeout`）。本机 SQLite 几乎不会遇到，但要有兜底（旧项目 `except` 吞异常导致「一直转圈」是同类问题）。

### 9.3 错误态

**四类错误，四套呈现**

| 类型 | 例子 | 呈现 | 组件 |
|---|---|---|---|
| **① 表单校验错误** | 代号重复、经纬度越界、级序号不连续 | 表单顶部 `alert-danger` 汇总 + 字段级 `is-invalid` | 见 4.7 的三层呈现 |
| **② 业务规则拒绝** | 重复执行已发射的任务；`PROTECT` 阻止删除引擎；`ProgramLink` 对象已归属其他计划 | `messages.error` → 页面顶部 `alert-danger`（**一次跳转后的提示**） | `_messages.html` |
| **③ 页面级错误** | 404（对象不存在）、403（未登录访问写操作）、500 | Django 默认错误页替换为自定义 `templates/404.html` / `403.html` / `500.html` | 见下 |
| **④ 局部失败（AJAX）** | `orbit_calc` 返回 500；`stage_reorder` 返回 400 | 就近显示内联提示，**不弹窗、不清空已有内容** | `.text-danger` 内联 div |

**② 类错误的文案规范（必须给解决路径，不能只说「失败」）**

| 场景 | 差文案 ❌ | 好文案 ✓ |
|---|---|---|
| 重复执行发射 | 「操作失败」 | 「无法执行 SCP-2026-014：当前状态为「已发射」，只有「计划中」或「发射准备」的任务可以执行发射。」 |
| 删除被引用的引擎 | 「ProtectedError」 | 「无法删除引擎 LV-909：它被 3 个级引用（Davy 2B 第 1 级、Mun Express 第 2 级…）。请先修改这些级，或改用「停用」标记。」 |
| 计划成员已归属 | 「唯一约束冲突」 | 「该火箭已归属计划「Mun 基地建设」。一个对象最多属于一个计划，请先把它从原计划移除。」 |
| 级序号冲突 | 「IntegrityError: UNIQUE constraint failed」 | 「该火箭已有第 2 级，请改用其他级序号（当前占用：1, 2, 3）。」 |
| 删除引擎时的 `PROTECT` | — | **删除确认页就要预警**（不是等到点删除才报错）：在 `engine` 详情页把「被引用的级」列出来，并在删除按钮上 `disabled` + tooltip「被 3 个级引用，不可删除」 |

**`PROTECT` 的界面预判（这是 brief 4.16 删除策略的界面落地）**

| 删除对象 | 预判查询 | 按钮状态 |
|---|---|---|
| `Engine` | `stage.engine = obj` 的级 | 有引用 → 按钮 `disabled` + tooltip + 列出引用它的级 |
| `FuelTank` | `stage_tank.fuel_tank = obj` | 同上 |
| `Body` | `site.body = obj` 或 `spacecraft.body = obj` 或 `body.parent = obj` | 同上（三种引用分别列出） |
| `CarrierModel` / `PayloadModel` / `Site` | `flight.carrier/payload/site = obj` | 有引用 → 按钮 `disabled` + 「被 n 条发射日志引用，发射历史不可删除；如需停用请用其他方式」 |
| 其余（`CASCADE`） | 统计将连带删除的子对象数 | 按钮可用 + 删除确认页列出「将连带删除：3 个级、5 条燃料罐挂载」 |

|---|---|---|

**结论**：**火箭编辑页的级 FormSet 是唯一「无 JS 即不可用」的核心功能**。这符合 brief D-13「动态级表单用 JS 克隆表格行」的定位，但要在 `08` 的验收里明确：

> **验收项**：级 FormSet 必须提供 `extra=2` 的服务端预渲染空行，使玩家在「JS 完全不可用」时**至少能通过反复保存来逐级累加**（保存 1 次加 1 级）。这是可接受的降级底线：不优雅，但不死锁。

| 类型 | 规范 | 示例 |
|---|---|---|
| 按钮 | 动词 + 名词，不用「确定/提交」这类泛词 | `+ 添加一级`、`执行发射`、`保存并返回详情` |
