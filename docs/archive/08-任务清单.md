## 1. 使用说明

### 1.1 这是什么

本文件是 **WBS（Work Breakdown Structure，工作分解结构）**，把 `_design-brief.md` 第 13 节的 P0–P4 五阶段骨架，逐层拆解为**可执行、可勾选、可验收**的开发任务。

- **不用它做设计**：字段名、枚举值、约束、路由、常数一律以 `_design-brief.md` 为准；本文件只回答「先做什么、做完什么算完」。
- **不引入新需求**：本文件出现的任何字段/路由都与 brief 一致；若发现不一致，见第 10.3 节的回改流程。

### 1.2 复选框与状态标记

```markdown
- [ ] 未开始
- [x] 已完成
- [~] 进行中（同一时刻全局建议不超过 3 个）
- [!] 阻塞（必须在第 11 节风险登记表中登记原因与负责人）
```

**约定**：
- 一个任务只有在**验收标准（该条目的「验收：」字段）实际跑通**后才能标 `[x]`，不允许「代码写完就算完」。
- 标 `[!]` 的任务必须在同一次提交里补上第 11 节的风险行；阻塞解除后改回 `[~]` 并记录解除日期。
- 每阶段末尾有 **Gate（阶段验收）** 区块，Gate 未全绿**不得开启下一阶段**。

### 1.3 任务编号体系

| 前缀 | 含义 | 示例 |
|---|---|---|
| `P0-xx` ～ `P4-xx` | 阶段任务（本阶段专属） | `P0-03`、`P2-17` |
| `X-xx` | 横切任务（跨阶段，不属于任何单一阶段） | `X-01` |
| `T-xx` | 测试任务（第 9 节集中列出） | `T-05` |
| `D-xx` | 文档任务（第 10 节） | `D-02` |
| `G-x` | 阶段验收 Gate | `G-0` |

> **⚠️ 编号一经分配，永不变更、永不复用。** 删除的任务保留编号并标注「已废弃」，新任务取当前最大值 +1。这样 `git commit` 信息、其他文档、issue 里都可以安全地写「完成 P2-11」。

### 1.4 任务粒度原则

- 每个任务应能在 **0.5 – 4 小时**内由一个人完成。
- **超过 4 小时的条目必须继续拆分**（本文件最长的是 `P2-13` 详情页模板，估 4h，已到上限）。
- 估算含「写完代码 + 自测通过」；不含代码评审（本项目单人不设评审）。
- 估算不含等待（如 conda 下载、`pip install` 网络时间）。

### 1.5 依赖与并行

- 「依赖：」字段为空的任务可立即开工。
- 「依赖：」里的编号**必须已标 `[x]`** 才能开工，不允许「先写着后面再补」。
- 单人串行时按编号顺序执行；若有多人，同一阶段内无相互依赖的条目可并行。
- 跨阶段依赖已在条目的「依赖：」中显式写出（例如 P2 的 `sites` 依赖 P0 的 `Body`）。

### 1.6 与本文件配套的命令速查

```powershell

python manage.py makemigrations

```

# 统计各阶段已完成 / 总数（在仓库根目录执行）
$lines = Get-Content docs/08-任务清单.md
foreach ($p in 'P0','P1','P2','P3','P4','X','T','D') {
  $total = ($lines | Select-String -Pattern "^- \[[ x~!]\] \*\*$p-").Count
  $done  = ($lines | Select-String -Pattern "^- \[x\] \*\*$p-").Count
  "{0}: {1}/{2}" -f $p, $done, $total
}
# 各阶段 Gate 单独统计（G-0.* / G-1.* …）
foreach ($g in 'G-0','G-1','G-2','G-3','G-4') {
  $t = ($lines | Select-String -Pattern "^- \[[ x~!]\] \*\*$g\.").Count
  $d = ($lines | Select-String -Pattern "^- \[x\] \*\*$g\.").Count

# 全量核对（应为 171 / 0）
"TOTAL: " + ($lines | Select-String -Pattern "^- \[[ x~!]\] \*\*").Count
