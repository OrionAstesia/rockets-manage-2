# rockets-manage-2 文档中心

> **项目**：《坎巴拉太空计划》(KSP) 发射计划与任务记录管理工具
> **前身**：`OrionAstesia/rockets-manage` — Flask + MySQL 火箭发射管理系统（原型，已归档）
> **文档版本**：v1.0 ｜ **定稿日期**：2026-09-19 ｜ **状态**：设计阶段完成，开发未开始

---

## 这个项目是什么

一个给 KSP 玩家自用的**发射计划与任务记录工具**。它回答五个问题：

| 我想知道 | 系统提供 |
|---|---|
| 我造过哪些火箭和载荷？它们的级是怎么配的？ | 部件库 + 火箭/载荷的**级结构**（级序、引擎、燃料罐） |
| 这枚火箭能不能把载荷送到目标轨道？ | **Δv 与推重比计算**（逐级累加） |
| 我接下来该发射什么？还没发射的任务有哪些？ | **发射日程**（`planned_ut` 待发任务） |
| 我在轨有哪些资产？它们的轨道和周期是多少？ | **在轨航天器**（轨道六要素 + 周期） |
| 这一堆东西是为了哪个目标在忙？ | **航天计划**（1 个计划统辖 n 个火箭/载荷/发射/发射场/航天器） |

## 技术栈一览

| 项 | 选择 | 一句话理由 |
|---|---|---|
| 框架 | **Django 5.2** | Admin 白送 14 张表的 CRUD，砍掉约 70% 工作量 |
| 数据库 | **SQLite**（单文件 `db.sqlite3`） | 游戏记录本形态，可直接拷贝备份 |
| Python 环境 | **conda 环境 `rocket`，Python 3.10** | 不污染其他项目的环境 |
| 计算 | **numpy** | 轨道与 Δv 的批量计算 |
| 前端 | Django 模板 + Bootstrap 5 + 原生 JS | 无构建链；动态级表单用 JS 克隆 `<template>` |
| 测试 | `manage.py test` | 比引入 pytest-django 少一层依赖 |

> ⚠️ **环境陷阱**：本机 PATH 上的 `python` 是 `D:\MinGW\bin\python.exe`（**没有 Django**）。运行本项目**必须先 `conda activate rocket`**。另本机 `conda` 不在 PATH 中（在 `F:\Anaconda\Scripts\conda.exe`）。详见 [09-新仓库启动说明.md](09-新仓库启动说明.md) §3.1。

## 两条关键术语约定（最易出错）

### 1. 「级间段」= 火箭的级（stage）
本项目里的「级间段」指的是**火箭的级**，不是 interstage/decoupler 分离环零件。这是经确认的语义（决策 D-07），详见 [02-概念模型.md](02-概念模型.md) 的术语映射表。

### 2. 级序方向（三处必须一致）
`stage_order = 1` 表示**最先点火、位于最下方的那一级**（起飞级），向上递增；页面按 `stage_order` **降序自上而下**渲染（最上级在顶部），而 Δv 从 `stage_order = 1` 起**升序**累加（算第 1 级时计入**上方所有级 + 载荷**质量）。

> 另一处同类陷阱：**`sma`（半长轴）不等于高度**，两者相差 `Body.radius`（Kerbin 为 600 km）。完整定义见基准 §4.8 与 [06-核心计算设计.md](06-核心计算设计.md) §13。

## 关于本仓库的交付范围

本仓库**只包含文档，没有代码**。设计阶段有意先冻结数据模型再动手实现——这是相对原型项目最大的改进（原型无迁移机制、无分层、无测试）。

**原型的去向**：`OrionAstesia/rockets-manage` 已**归档保存、保持不动**，作为历史参考。旧代码（`manage.py`、`mysql_util.py`、`forms.py`、`arock.sql`、`templates/`、`random_generator/` 等）留在那个仓库里，**不在本仓库**。

> ⚠️ 因此阅读 [07-重构方案与实施计划.md](07-重构方案与实施计划.md) 时请注意：其中引用旧代码的**文件路径与行号**（如 `manage.py:28`、`forms.py:15`）指向**已归档的原型仓库**。`07` 的 §2–§8、§14–§15 属于历史记录与设计由来，**不是本仓库的开工清单**——开工清单是 [08-任务清单.md](08-任务清单.md)。
