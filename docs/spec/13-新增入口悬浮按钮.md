## 2. 改造后的统一规则

### 2.1 按钮的外观与位置

```html
<button type="button" class="btn btn-primary rounded-circle app-fab"
        data-open-dialog="dlg-new" aria-label="新增" title="新增">
  <span class="app-fab-plus">+</span>
</button>
```

| 项 | 规定 |
|---|---|
| 位置 | **视口右下角**，`position: fixed`（**不随页面滚动**——这是本次的核心要求） |
| 形状 | 圆形 |
| 尺寸 | 直径 3.5rem（56px），足以触摸 |
| 内容 | 一个「+」文本，**不引图标库**（`font-size: 1.75rem` 即可，与项目「不引新依赖」一致） |
| 无障碍 | 必须有 `aria-label="新增"`；`title` 可给提示 |
| 触发 | `data-open-dialog="dlg-new"` —— 复用 `12` 的 JS，**JS 不需要为本次改动任何代码** |

### 2.2 CSS（加在 `base.html` 的 `<style>` 里，不新建 `.css` 文件）

```css
.app-fab {
  position: fixed;
  right: 1.5rem;
  bottom: 1.5rem;
  z-index: 1030;              /* 高于内容、低于 <dialog> 的遮罩 */
  width: 3.5rem;
  height: 3.5rem;
  padding: 0;
  display: flex;
  align-items: center;
  justify-content: center;
  box-shadow: 0 .25rem .75rem rgba(0, 0, 0, .3);
}
.app-fab-plus {
  font-size: 1.75rem;
  line-height: 1;
  /* 让「+」视觉居中：文本基线比几何中心偏下，往上挪一点 */
  transform: translateY(-1px);
}
```

**`z-index` 的取值的依据**：Bootstrap 的 `sticky`/`fixed` 组件在 1020–1030 区间；原生 `<dialog>` 的遮罩（`::backdrop`）在浏览器内部层级里**始终高于普通定位元素**，所以 `1030` 不会被弹窗盖住、也不会盖住弹窗。

## 3. 模板改造：一处新增，多处删除

### 3.1 `base.html` 新增一个 block

FAB 是**页面级**的（哪一页有、哪一页没有不同），所以用模板块让子模板决定：

```html
  {# ── 右侧内容区 ─────────────────────────────────────── #}
  <div class="flex-grow-1 min-vw-0">
    {% block subnav %}{% endblock %}
    <main class="container-fluid px-4 py-4 app-main">
      {% for message in messages %}
      <div class="alert alert-{{ message.tags }} alert-dismissible">{{ message }}</div>
      {% endfor %}
      {% block content %}{% endblock %}
    </main>
  </div>

</div>

{# ── 悬浮新增按钮：由子模板用 {% block fab %} 决定是否出现 ── #}
{% block fab %}
<button type="button" class="btn btn-primary rounded-circle app-fab"
        data-open-dialog="dlg-new" aria-label="新增" title="新增">
  <span class="app-fab-plus">+</span>
</button>
{% endblock %}
</body>
```

**注意 `{% block fab %}` 放在 `</div>`（flex 容器）之后、`</body>` 之前** —— 因为 `position: fixed` 不受父容器影响，但放在 flex 容器内会多一层参与布局的元素，放外面最干净。

### 3.2 需要 FAB 的模板：什么都不用写

`base.html` 的 `{% block fab %}` **默认就输出按钮**，所以 10 个需要 FAB 的页面**一个字都不用改**（除了 §2.4 的删除与 §2.5 的文案）。

### 3.3 不需要 FAB 的模板：覆写为空

只有 4 类页面需要显式关掉：

| 文件 | 加什么 |
|---|---|
| `templates/core/home.html`（主页） | `{% block fab %}{% endblock %}` |
| `templates/ops/schedule.html`（日程） | 同上 |
| `templates/parts/body_list.html`（天体，只读） | 同上 |
| `templates/form.html` / `templates/confirm_delete.html` | **`12` 会删掉这两个模板**，若保留则也要覆写为空 |

> **`12` 若已实施**，`form.html` 与 `confirm_delete.html` 已不存在，只需处理前三个。
>
> **采用「默认有、个别关掉」而非「默认无、逐个打开」** 是有意的：需要 FAB 的页面有 10 个、不需要的只有 3 个，**默认开着更省改动，也减少漏加的风险**。

## 7. 易踩的坑

1. **`{% block fab %}` 要放在 flex 容器之外**（`</div>` 之后）。放进 `.d-flex` 里会让它成为一个 flex item，`position: fixed` 虽然仍生效，但父容器的高度计算会受影响。
2. **`<main>` 必须加 `padding-bottom`**（`.app-main`），否则 FAB 会盖住表格最后一行的操作列——在数据只有 1–2 行的页面上尤其明显。
3. **`z-index` 不要调高到 1040 以上**，也不要设成 `9999`。原生 `<dialog>` 的遮罩层由浏览器管理，普通元素的 `z-index` 不会盖住它；设得过高反而在将来引入其他浮层时出问题。
4. **不要用 `position: sticky`** 代替 `fixed` —— `sticky` 需要滚动祖先，这里没有，会退化成静态定位（**正是"随滚动移动"的错误效果**）。
5. **空状态文案是本次最容易漏的**（**10 处**：5 处在 `ops/`、3 处在 `parts/`、1 处在 `fleet/`、1 处在 `core/save_list.html`）。§2.5 有逐行清单，照抄。
   ⚠️ 注意 `core/save_list.html:63` 写的是**「用上面的表单新建一个」**，不含「右上角」字样，**按关键词搜「右上角」时找不到它**。
6. **`/reference/bodies/` 必须显式关掉 FAB**：它是只读页，若默认开着就会出现一个点开为空弹窗的按钮。
7. **`/schedule/` 也要关掉**：那是跨存档的日程视图，没有「新增到哪个存档」的语义。
8. **别给 FAB 加 `type="submit"`**：必须是 `type="button"`，否则若它恰好落在某个 `<form>` 内（将来可能），点击会提交表单。
9. **无障碍别漏 `aria-label`**：按钮里只有一个 `+` 字符，读屏软件会念成「加号」，不知道是干什么的。
10. **删除顶部入口时不要连带删掉「共 N 个」计数** —— 那是有用信息，只把按钮移走。
