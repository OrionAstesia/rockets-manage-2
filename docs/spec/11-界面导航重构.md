## 1. 改造目标

### 1.1 现状的两个问题

| 问题 | 现状 |
|---|---|
| 导航是顶部的 | `templates/base.html` 用 Bootstrap `navbar` 横排在页面顶部，只有 3 个链接（存档 / 参考数据 / 发射日程） |

## 4. 视图改造

### 4.1 新增一个共用基类 `SaveScopedListView`（放 `core/views.py`）

5 个存档列表页都只是「取某个存档的某个集合」，用一个基类消除重复：

```python
class SaveScopedListView(ListView):
    """存档下的一个集合列表（`/saves/<pk>/<slug>/`）。

    子类只需给 `model`、`template_name`、`var_name`（模板里的上下文变量名）、
    可选的 `select_related` / `annotate`。
    """

    save = None

    def dispatch(self, request, *args, **kwargs):
        self.save = get_object_or_404(Save, pk=kwargs["pk"])
        return super().dispatch(request, *args, **kwargs)

    def get_queryset(self):
        qs = self.model.objects.filter(program=self.save)
        return qs.select_related(*self.select_related) if self.select_related else qs

    def get_context_data(self, **kwargs):
        ctx = super().get_context_data(**kwargs)
        ctx["save"] = self.save
        return ctx
```

**注意 `model` 上必须是 `program` 外键**（绝不能写成 `save`，那会遮蔽 `Model.save()`）。`Rocket` / `Payload` / `Site` / `Spacecraft` / `FlightLog` 五张表都有 `program`。

5 个子类（放 `ops/views.py`，因为 URL 前缀是 `/saves/`；**它们从别的 app 取模型是允许的，`ops` 本来就已经 import 了 `fleet`/`spaceflight`/`parts` 的模型**）：

```python
class SaveRocketsView(SaveScopedListView):
    model = Rocket
    template_name = "ops/save_rockets.html"
    context_object_name = "rockets"
    select_related = ()

    def get_queryset(self):
        # 需要「级数」列，所以 annotate 一次，避免每行一次 count 查询
        return (super().get_queryset()
                .annotate(stage_total=Count("stages")))

class SavePayloadsView(SaveScopedListView):
    model = Payload
    template_name = "ops/save_payloads.html"
    context_object_name = "payloads"

class SaveSitesView(SaveScopedListView):
    model = Site
    template_name = "ops/save_sites.html"
    context_object_name = "sites"
    select_related = ("body",)

class SaveSpacecraftView(SaveScopedListView):
    model = Spacecraft
    template_name = "ops/save_spacecraft.html"
    context_object_name = "spacecraft_rows"
    select_related = ("body",)

    def get_queryset(self):
        # 周期要实时算（不落库），所以这里返回带 period 的字典列表
        return [{"obj": sc, "period": period_text(sc)} for sc in super().get_queryset()]

class SaveFlightsView(SaveScopedListView):
    model = FlightLog
    template_name = "ops/save_flights.html"
    context_object_name = "flight_rows"
    select_related = ("rocket", "site")

    def get_queryset(self):
        return [{"obj": f, "result": result_text(f)} for f in super().get_queryset()]
```

> ⚠️ `SaveSpacecraftView` 与 `SaveFlightsView` 返回的是**列表**而不是 queryset，`ListView` 的 `paginate_by` 为 `None` 时能正常工作（不会分页）。**不要**给这两个视图设 `paginate_by`。
>
> `period_text()` 与 `result_text()` 两个辅助函数**已有实现**，现在在 `ops/views.py` 里，**原样保留**。

### 7.3 断言的写法提醒

「不在主页高亮」这类**否定断言**用 `assertNotContains(response, '...')` 时，要选一段**只在 active 版本里出现**的片段，否则会误判。稳妥做法是断言具体 HTML 片段，例如：

```python
# 存档项的 active 版本包含 class="nav-link text-white active"
self.assertNotContains(response, 'text-white active"', html=True)
```

`html=True` 会按 HTML 规范化后比较，避免空格/换行差异造成的伪失败。

## 11. 易踩的坑

1. **`{% block subnav %}` 的位置**：必须放在 `base.html` 的**右侧内容区顶部**、`<main>` 之前。放错位置会让二级导航跑到侧栏里。
2. **`SaveScopedListView` 的过滤字段是 `program`**，不是 `save`。写成 `save=` 会 `TypeError: 'Save' object is not callable`（`manage.py check` 查不出来）。
3. **`request.resolver_match` 在 `base.html` 里可用**，但它在 404/500 页面上可能为 `None`。**判断前不加保护也能跑**（Django 模板对 `None.namespace` 静默返回空），但不要对它做算术或方法调用。
4. **`context_object_name` 与模板变量名必须一致**：火箭页用 `rockets`、载荷用 `payloads`、发射场用 `sites`、航天器用 `spacecraft_rows`（字典列表）、发射日志用 `flight_rows`（字典列表）。改错会得到**空白表格且不报错**。
5. **`SaveSpacecraftView` / `SaveFlightsView` 返回列表，不是 queryset** → 不要设 `paginate_by`，否则 `ListView` 会报错。
6. **N+1 查询**：`SaveSitesView` / `SaveSpacecraftView` 必须 `select_related("body")`，`SaveFlightsView` 必须 `select_related("rocket", "site")`，`SaveRocketsView` 必须 `annotate(Count("stages"))`。漏掉会在数据变多后变慢。
7. **忘了改 `save_list.html` 与 `rocket_detail.html` 的链接** → 页面能跑，但每次点存档名都多一次 302。
8. **`/reference/` 忘了加重定向** → 侧栏「参考数据」如果还指向 `/reference/` 就 404。侧栏已改成直接指向 `parts:engine_list`，但**仍要保留 `/reference/` 的重定向**，防止你书签里存着旧地址。
9. **删掉 `workspace.html` / `reference.html` 前先确认没有别的模板 `{% include %}` 它们**（当前没有，但删之前 grep 一次）。
10. **`ops/urls.py` 里 `save_rockets` 等 5 条要放在 `saves/<int:pk>/` 之前**，保持阅读顺序与匹配直觉一致。
11. **别把 `/saves/` 与 `saves/new/` 的匹配顺序弄反**：两者都在 `core/urls.py` 里，`path("saves/", ...)` 是精确匹配、不会吃掉 `saves/new/`。但**顺序写成 `saves/` 在后也无所谓**——真正要小心的是别把 `saves/` 写成 `saves/<path:...>` 之类的宽松模式。
12. **改 `HomeView` 时别顺手把统计块留下**：`SaveListView` 要用 `Count` / `Spacecraft` / `FlightLog`，这些 import 现在在 `core/views.py` 顶部，搬视图时**不要一起删掉**，否则 `NameError`。
13. **别忘了 `core/tests.py` 的两类 `core:home` 引用改法不同**（§7.1）。一律替换会让「首页渲染测试」变成「拿空主页去断言存档表格」，直接失败。
14. **模板里还有一处 `core:home` 容易漏**：`templates/ops/schedule.html` 的返回链接。`grep` 核对（§7.1 末尾给了命令）。
