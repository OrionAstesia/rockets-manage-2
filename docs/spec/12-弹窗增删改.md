## 1. 改造目标

| 项 | 改造前 | 改造后 |
|---|---|---|
| 增删改的入口 | 每组 CRUD **3 条独立路由**（`/xxx/new/`、`/xxx/<pk>/edit/`、`/xxx/<pk>/delete/`），各自一个表单页 / 确认页 | **原地弹窗**，**不加任何路由** |

## 4. 提交协议（本次改造的核心约定）

### 4.1 一个 POST 端点，靠 `action` 分流

每个列表页的 **GET 渲染列表 + 空表单**；**POST 处理三种动作**：

```
POST /saves/3/payloads/
    action=create                → 新建（表单字段来自 body）
    action=update  & pk=7        → 修改 id=7
    action=delete  & pk=7 & confirmed=yes   → 删除 id=7
```

表单里的**固定隐藏字段**：

| 字段 | 何时出现 | 值 |
|---|---|---|
| `action` | 总是 | `create` / `update` / `delete` |
| `pk` | `update` / `delete` | 目标对象 id |
| `confirmed` | **只有删除** | `yes` |

> **为什么删除需要 `confirmed=yes`**：防止误点与 CSRF 之外的重放。列表行上的「删除」按钮只负责**打开确认弹窗**（纯前端行为，不发请求）；弹窗里的表单才带 `confirmed=yes`。这样「删除是 POST」与「不能一点就删」两个要求同时满足——沿用改造前 `SafeDeleteMixin` 的思路，只是确认界面从独立页面变成了弹窗。

### 4.2 服务端处理顺序

```
POST 到达
 ├─ action 缺失或非法 → messages.error + redirect 回自己
 ├─ action == delete
 │   ├─ confirmed != "yes" → messages.error + redirect 回自己（正常流程不会出现）
 │   ├─ 取对象（必须属于本存档/本页）→ 不存在 → messages.error + redirect
 │   └─ obj.delete() → ProtectedError → messages.error + redirect；成功 → messages.success + redirect
 └─ action == create / update
     ├─ 构造 ModelForm(data=request.POST, instance=obj_or_None)
     ├─ 校验失败 → **重新渲染列表页**（不 redirect），并把该弹窗标记为「需打开」，同时显示错误
     └─ 成功 → messages.success + **redirect 回自己**（POST-Redirect-GET，防刷新重复提交）
```

**只有校验失败时 `render`，其余一律 `redirect`。**

### 4.3 校验失败怎么让弹窗重新打开

**服务端**在渲染时给对应 `<dialog>` 加一个 `data-open` 属性，并把它要打开的 `pk` 放进上下文：

```python
ctx["open_dialog"] = "edit"          # "create" | "edit" | "delete"
ctx["open_pk"] = obj.pk              # edit / delete 时有值
```

**模板**在 `<dialog>` 上条件输出：

```html
<dialog class="modal" id="dlg-{{ obj.pk }}"
        {% if open_dialog == "edit" and open_pk == obj.pk %}data-open="1"{% endif %}>
```

**JS** 在 `DOMContentLoaded` 时找 `[data-open]` 并 `showModal()`。

## 5. 视图改造

### 5.1 新基类：`SaveScopedCrudView`（替换 `SaveScopedListView`）

`core/views.py` 里把 `SaveScopedListView` 升级成同时处理 GET/POST 的基类：

```python
class SaveScopedCrudView(ListView):
    """存档下某个集合的「列表 + 弹窗增删改」，全部走这一个 URL。

    GET  → 渲染列表 + 空的新建表单（+ 每行的编辑/删除弹窗表单）
    POST → 按 `action` 字段分流：create / update / delete

    子类必须给：model（有 `program` 外键）、form_class、template_name、
                context_object_name、以及可选的 select_related / annotate_extra
    """

    save = None
    open_dialog = None      # "create" / "edit" / "delete"，校验失败时设值
    open_pk = None

    def dispatch(self, request, *args, **kwargs):
        self.save = get_object_or_404(Save, pk=kwargs["pk"])
        return super().dispatch(request, *args, **kwargs)

    def get_queryset(self):
        qs = self.model.objects.filter(program=self.save)      # ★ 字段名是 program
        if self.select_related:
            qs = qs.select_related(*self.select_related)
        return qs

    def get_context_data(self, **kwargs):
        ctx = super().get_context_data(**kwargs)
        ctx["save"] = self.save
        ctx["form"] = self.form_class(program=self.save)        # 新建用的空表单
        ctx["open_dialog"] = self.open_dialog
        ctx["open_pk"] = self.open_pk
        return ctx

    # ---------- POST ----------
    def post(self, request, *args, **kwargs):
        action = request.POST.get("action")
        if action == "delete":
            return self._handle_delete(request)
        if action in ("create", "update"):
            return self._handle_save(request, action)
        messages.error(request, "未知操作。")
        return redirect(request.path)

    def _handle_save(self, request, action):
        instance = None
        if action == "update":
            instance = self.get_object_or_none(request.POST.get("pk"))
            if instance is None:
                messages.error(request, "要修改的记录不存在。")
                return redirect(request.path)

        form = self.form_class(request.POST, instance=instance, program=self.save)
        if not form.is_valid():
            # 不 redirect：把错误连同列表一起渲染，并让弹窗重新打开
            self.open_dialog = action
            self.open_pk = instance.pk if instance else None
            self.object_list = self.get_queryset()
            ctx = self.get_context_data(form=form)
            return self.render_to_response(ctx)
        form.save()
        messages.success(request, "已保存。" if instance else "已新增。")
        return redirect(request.path)

    def _handle_delete(self, request):
        if request.POST.get("confirmed") != "yes":
            messages.error(request, "删除未确认。")
            return redirect(request.path)
        obj = self.get_object_or_none(request.POST.get("pk"))
        if obj is None:
            messages.error(request, "要删除的记录不存在。")
            return redirect(request.path)
        try:
            obj.delete()
        except ProtectedError as exc:
            messages.error(
                request, f"删除失败：仍有数据引用它（{protected_names(exc)}），请先处理。"
            )
            return redirect(request.path)
        messages.success(request, "已删除。")
        return redirect(request.path)

    def get_object_or_none(self, pk):
        """只允许操作**属于本存档**的对象（防越权改别人的数据）。"""
        if not (pk and str(pk).isdigit()):
            return None
        return self.model.objects.filter(pk=pk, program=self.save).first()
```

**⚠️ 三个关键点**：

1. **`get_object_or_none` 必须同时按 `program` 过滤。** 只按 `pk` 过滤的话，把 `pk` 改成别的存档的 id 就能改到别人的数据。
2. **`form_class(..., program=self.save)`** —— 依赖 `ProgramScopedFormMixin`（已存在于 `core/forms.py`）。编辑时传 `instance`，`program` 会自动从实例读；但显式传 `program` 更安全。
3. **`get_context_data(form=form)`** 用于把校验失败的表单（带错误 + 用户输入）传给模板。

class CrudListView(ListView):

    与 SaveScopedCrudView 的唯一区别：`get_object_or_none` 不按 program 过滤，

        ctx["open_dialog"] = self.open_dialog

**为了让两个基类不重复**，把公共部分抽成一个 `DialogCrudMixin`（`post` / `_handle_save` / `_handle_delete` 三个方法），两个基类各自只实现「取对象」与「构造表单」两个钩子：

```python
class DialogCrudMixin:
    def get_scoped_object(self, pk): ...      # 子类实现：怎么按 pk 取且校验归属
    def build_form(self, data, instance): ... # 子类实现：怎么构造 ModelForm

class SaveScopedCrudView(DialogCrudMixin, ListView): ...
class CrudListView(DialogCrudMixin, ListView): ...
```

> 这是本次唯一值得做的抽象——两个基类的 `post` 逻辑完全相同（约 40 行），复制两份必然漂移。

## 6. 模板改造

### 6.1 通用弹窗骨架（新增 `templates/includes/_dialog.html`）

**用一个 include 承载所有弹窗的重复结构**，避免 30 个弹窗各写一遍十几行：

```html
{# 参数：dialog_id, title, form, action, pk=None, confirm_text=None, danger=False #}
<dialog class="modal" id="{{ dialog_id }}"
        {% if open_dialog %}{% if open_dialog == action|default:"" %}data-open="1"{% endif %}{% endif %}>
  <div class="modal-dialog modal-dialog-centered">
    <div class="modal-content">
      <form method="post" novalidate>
        {% csrf_token %}
        <input type="hidden" name="action" value="{{ action }}">
        {% if pk %}<input type="hidden" name="pk" value="{{ pk }}">{% endif %}
        {% if action == "delete" %}<input type="hidden" name="confirmed" value="yes">{% endif %}

        <div class="modal-header">
          <h5 class="modal-title">{{ title }}</h5>
          <button type="button" class="btn-close" data-close-dialog aria-label="关闭"></button>
        </div>

        <div class="modal-body">
          {% if action == "delete" %}
            <p>{{ confirm_text }}</p>
          {% else %}
            {% for field in form %}
              <div class="mb-3">
                {% if field.field.widget.input_type == "checkbox" %}
                  <div class="form-check">{{ field }}<label class="form-check-label" for="{{ field.id_for_label }}">{{ field.label }}</label></div>
                {% else %}
                  <label class="form-label" for="{{ field.id_for_label }}">{{ field.label }}{% if field.field.required %} <span class="text-danger">*</span>{% endif %}</label>
                  {{ field }}
                {% endif %}
                {% if field.help_text %}<div class="form-text">{{ field.help_text }}</div>{% endif %}
                {% for error in field.errors %}<div class="text-danger small">{{ error }}</div>{% endfor %}
              </div>
            {% endfor %}
            {% if form.non_field_errors %}
              <div class="alert alert-danger">{% for e in form.non_field_errors %}<div>{{ e }}</div>{% endfor %}</div>
            {% endif %}
          {% endif %}
        </div>

        <div class="modal-footer">
          <button type="button" class="btn btn-outline-secondary" data-close-dialog>取消</button>
          <button type="submit" class="btn {% if danger %}btn-danger{% else %}btn-primary{% endif %}">
            {% if action == "delete" %}确认删除{% else %}保存{% endif %}
          </button>
        </div>
      </form>
    </div>
  </div>
</dialog>
```

> **`form` 的 id 前缀问题**：多个弹窗渲染同一个 `form` 对象时，字段的 `id_xxx` 会重复，`<label for>` 会指错。**解决办法**：给每个弹窗的表单字段加 `prefix`。
> 最省事的做法是在视图里给每行的编辑表单加 prefix：
> ```python
> ctx["edit_forms"] = {
>     obj.pk: self.form_class(instance=obj, program=self.save, prefix=f"e{obj.pk}")
>     for obj in object_list
> }
> ```
> 这样 `id` 变成 `id_e7_name`，不会重名。**新建表单用 `prefix="new"`。**
> 但这样模板里要按行取对应表单，略啰嗦。**折中方案（推荐）**：只给**新建表单**加 prefix，每行的编辑表单也用**各自 pk 作 prefix**，通过一个 dict 传入。**同一时刻页面上只有几十个表单，不会冲突。**

### 6.2 各列表页的改造（`ops/save_*.html`、`parts/*_list.html`）

## 7. JavaScript（唯一新增的前端代码）

### 7.1 `static/js/modal.js`（约 30 行）

```js
// 弹窗控制：只做开关与 Esc 关闭，不做 AJAX、不做前端校验。
document.addEventListener("DOMContentLoaded", () => {
  // 1. 点击带 data-open-dialog 的按钮 → 打开对应 <dialog>
  document.body.addEventListener("click", (event) => {
    const opener = event.target.closest("[data-open-dialog]");
    if (opener) {
      const dialog = document.getElementById(opener.dataset.openDialog);
      if (dialog) dialog.showModal();
    }
    if (event.target.closest("[data-close-dialog]")) {
      const dialog = event.target.closest("dialog");
      if (dialog) dialog.close();
    }
  });

  // 2. 点遮罩（dialog 自身区域）关闭 —— 原生 <dialog> 有此行为，这里只处理点击空白
  document.querySelectorAll("dialog.modal").forEach((dialog) => {
    dialog.addEventListener("click", (event) => {
      if (event.target === dialog) dialog.close();
    });
  });

  // 3. 服务端校验失败时，自动重新打开标记过的弹窗
  const toOpen = document.querySelector("dialog[data-open]");
  if (toOpen) toOpen.showModal();
});
```

**注意**：
- 用 `<dialog>` 的**原生 `showModal()` / `close()`**，不引 Bootstrap JS。
- **不要用 `alert()` / `confirm()`**（那是浏览器原生框，样式与页面不一致）。
- **提交表单后不要 `preventDefault`**——正常 POST 由浏览器完成。

### 7.2 `base.html` 引入

```html
<script src="{% static 'js/modal.js' %}" defer></script>
```

- 需要在 `base.html` 顶部加 `{% load static %}`
- `defer` 保证 DOM 就绪后执行
- **不要**引 Bootstrap 的 JS bundle（用不上，且体积大）

### 7.3 弹窗样式

Bootstrap 的 `.modal` / `.modal-dialog` / `.modal-content` 类**在没有 Bootstrap JS 时依然能显示**，因为 `<dialog>` 原生就有遮罩与居中能力。需要补一小段 CSS 让 `<dialog>` 本身有尺寸：

```css
dialog.modal { border: none; padding: 0; background: transparent; max-width: 100vw; }
dialog.modal::backdrop { background: rgba(0, 0, 0, .5); }
dialog.modal .modal-dialog { min-width: min(560px, 92vw); }
```

放在 `base.html` 的 `<style>` 里（不新建 `.css` 文件，与现状一致）。

## 11. 易踩的坑（逐条核对）

1. **`action` 字段名不要改**：`action` 也是 HTML `<form>` 的合法属性名，**但它作为 `<input name="action">` 与 `<form action="...">` 不冲突**。不要为了"避免歧义"把它改名成 `op` 之类——文档与测试都按 `action` 写。
2. **删除必须带 `confirmed=yes`**，否则「行上的删除按钮」与「弹窗里的确认」会被混为一谈。行上按钮**只开弹窗，不发请求**。
3. **`get_object_or_none` 必须按 `program` 过滤**，否则可以通过改 `pk` 越权操作别的存档的数据。§8.2 有专门的测试卡这个。
4. **校验失败不能 `redirect`**：必须 `render`，否则弹窗里的错误与用户输入全丢。这是本次最容易做错的一处。
5. **`form` 的 `prefix`**：同一页面上有「新建表单 + N 个编辑表单」，**不加 prefix 会出现重复 `id`**，`<label for>` 指错、浏览器可能把值填到错误的框里。每个表单用不同的 prefix（新建用 `new`，编辑用 `e<pk>`）。
6. **`_dialog.html` 里的 `open_dialog` / `action` 比较**：include 的 `with` 不会继承外层上下文的全部变量（除非用 `only` 时才不继承——默认继承）。（默认会继承，所以 `open_dialog` 可用。**不要加 `only`**。）
7. **`<dialog>` 的 `showModal()` 在同一元素上重复调用会抛错**：`data-open` 的自动打开逻辑要确保只对有 `[data-open]` 的元素调一次。
8. **`ProtectedError.protected_objects` 是 `set`**，**不能切片**。用现有的 `protected_names(exc)` 辅助函数（已经在 `core/views.py`）。
9. **`save_list.html` 的删除弹窗要保留「连带删除数量」**，这是改造前就有的重要信息，别在改弹窗时丢掉。
10. **`Save.delete()` 的级联顺序不能丢**：它在模型层实现（先删 `spacecraft` 与 `flights`），视图改造不涉及它，但**删除走弹窗后仍会经过它**——不要在视图里绕过 `obj.delete()` 直接删关联。
11. **`rows` 循环变量的改动要同步模板**：§6.2 提到把 `{% for obj in rockets %}` 改成 `{% for row in rows %}` 并用 `row.obj`。**漏改会导致表格空白且不报错**。
12. **删 `form.html` 前先 grep `form.html`**：`FormPageMixin` 与各 `*CreateView` 都用 `template_name = "form.html"`，删模板前先删视图。
13. **删掉 `FormPageMixin` 家族后，四个 app 的 `views.py` 都要同步清理 import**（实测各处导入的正是这些名字），否则 `ImportError`：

    | 文件 | 要删掉的导入 |
    |---|---|
    | `fleet/views.py:8` | `FormPageMixin` / `SafeDeleteMixin` / `ScopedCreateView` / `ScopedDeleteView` / `ScopedUpdateView`（**5 个都要删**） |
    | `ops/views.py:11` | `ScopedCreateView` / `ScopedDeleteView` / `ScopedUpdateView`（保留 `SaveScopedListView` 的继任者） |
    | `spaceflight/views.py:6` | `ScopedCreateView` / `ScopedDeleteView` / `ScopedUpdateView` |
    | `parts/views.py:12` | `FormPageMixin` / `SafeDeleteMixin` |

    同时各文件的 `from django.views.generic import ...` 也会剩下一堆用不到的 `CreateView` / `DeleteView` / `UpdateView`，一起清掉。
14. **`static/` 目录当前不存在**（实测确认；`base.html` 只引 CDN）。好消息是 `settings.py` 已经就绪：`django.contrib.staticfiles` 在 `INSTALLED_APPS`（第 40 行）、`STATIC_URL = 'static/'`（第 125 行）。所以**只需新建 `static/js/modal.js`**，开发模式下 `{% static %}` 会自动找到它（`runserver` 自带静态文件服务）。不需要配 `STATIC_ROOT`、不需要 `collectstatic`。

## 12. 实施补充（已落地，与本文的差异 / 本文没写到的坑）

1. **`static/` 必须列进 `STATICFILES_DIRS`**：§11.14 说「只需新建 `static/js/modal.js`，开发模式下会自动找到」**不成立**。Django 只按 finder 找文件，项目根的 `static/` 不在默认 finder 里 —— `{% static %}` 能拼出 `/static/js/modal.js`，但 `runserver` 会 404。已在 `settings.py` 加 `STATICFILES_DIRS = [BASE_DIR / "static"]`（仍然不需要 `STATIC_ROOT` / `collectstatic`）。
2. **prefix 要让服务端知道**：§6.1 要求给每个弹窗的表单加 `prefix`，但校验失败重渲染时服务端得用**同一个前缀**重建绑定表单，否则字段名对不上、错误与用户输入全丢。做法：`includes/_dialog.html` 里额外放一个隐藏字段 `<input type="hidden" name="prefix" value="{{ prefix }}">`，视图从 `request.POST["prefix"]` 取回（新建 `new`、每行 `e<pk>`）。副作用是 **id 不再重复**，§11.15 那条担心不存在了。
3. **`{pk: 文本}` 字典在模板里取不出来**：§5.2 建议航天器/发射日志用 `ctx["periods"] = {pk: 文本}` 再在模板里查表 —— Django 模板**不支持用变量做字典下标**（`periods[row.obj.pk]` 语法无效）。已改为在 `get_rows()` 里把派生值挂到行上：`row["period"]` / `row["result"]`。
4. **`spaceflight` 已无 URL**：§2.2 删掉它的 6 条路由之后，`spaceflight/urls.py` 里什么都不剩；已把 `spaceflight/urls.py` 与 `spaceflight/views.py` 一并删除，并去掉 `config/urls.py` 里的 include（发射场/航天器分别在 `/saves/<pk>/sites|spacecraft/` 上维护）。
5. **顺带修一个既有隐性 bug**：Django 的 `{# #}` 注释**不能跨行** —— 跨行时不会被当注释，而是当普通文本输出，里面的 `{% %}` 还会被真的解析（`base.html` 的跨行注释里写了 `{% block fab %}`，直接导致 `TemplateSyntaxError: block 'fab' appears more than once`）。模板里的跨行注释已全部改为单行。
6. **测试数变化**：改造前 158 项 → 删掉 5 项已无意义的（新建页渲染、缺 `save` 参数）后 153 → 删掉「旧 `/saves/<pk>/` 302」1 项后 152 → 补第 8.2 节与文档 13 第 5 节的新测试后 **168 项**。
7. **实际分步**：本文 §9 的 A–F 被拆成 6 个「每步都全绿」的提交（先加弹窗机制与 FAB，再按模块把视图+模板+测试一起翻过来，最后删路由/旧视图/旧模板）。
