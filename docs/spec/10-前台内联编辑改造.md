## 1. 改造目标

把**所有增删改从 Django Admin 移到前台页面**，因为这是个人自用工具，Admin 的下拉选择器与外键手选太繁琐。

**关键改进点**：前台在「某个存档」的上下文里操作时，`program`（所属存档）**由页面自动填，不再让用户选**。

**Admin 的处理**：**保留代码，但前台不放任何入口**（不从导航链接过去，不在页面里放「在后台编辑」按钮）。`/admin/` 仍可直接访问，仅作偶发兜底。

## 3. 数据模型：不要改

11 张表已实现，**本次改造不动任何字段、枚举、约束、`on_delete`、迁移**。

**必须知道的既有约定**（改视图/表单时会用到）：

| 模型 | 关键点 |
|---|---|
| `ops.Save` | 存档，全部数据的根。字段：`name`（唯一）/ `start_date` / `game_mode`。**它有自定义 `delete()`**：先级联删自己的 `spacecraft` 与 `flights`，再 `super().delete()`，整体包在 `transaction.atomic()` 里。原因：`FlightLog` 以 `PROTECT` 引用 `Rocket`/`Payload`/`Site`，Django 的删除收集器会因此拦住删存档 |
| `fleet.Rocket` / `fleet.Payload` / `spaceflight.Site` / `spaceflight.Spacecraft` / `ops.FlightLog` | 各有一个**必填**外键指向 `Save`，**属性名是 `program`** |
| `fleet.RocketStage` | 挂在 `Rocket` 上（`rocket` 外键，CASCADE），有 `stage_order`（1 = 最先点火的最下面一级，向上递增）、`engine` / `engine_count` / `fuel_tank` / `tank_count` / `structure_mass` / `separation_type` / `note`。约束：`UniqueConstraint(["rocket", "stage_order"])` |
| `core.Body` | 天体，只读参考数据（由 `fixtures/bodies.json` 提供，6 条） |
| `parts.Engine` / `parts.FuelTank` / `parts.ScienceInstrument` | 参考数据，跨存档共用，**没有** `program` 外键 |
| `ops.FlightLog` | `state`（`PLANNED`/`LAUNCHED`/`FAILED`/`CANCELLED`）、`planned_date`、`actual_date`、`result_code`（留空 / -1 / 0 / >0）、`rest_dv`、`rocket`（必填，PROTECT）、`payload`（可空，PROTECT）、`site`（必填，PROTECT）、`detail` |

### ⚠️ 铁律：外键属性名必须是 `program`，不能叫 `save`

`save` 会遮蔽 Django 的 `Model.save()`，导致 `objects.create()` 和任何保存操作抛 `TypeError: 'Save' object is not callable`，而 `manage.py check` 与 `makemigrations` **都查不出来**。

**本次新增的视图与表单必须写 `program=`，不是 `save=`。**

### 各模型的状态校验（已写在 `models.py` 的 `clean()` 里）

| 模型 | `clean()` 校验 |
|---|---|
| `Site` | 纬度 -90..90；经度 -180..180 |
| `Spacecraft` | `sma > body.radius`（并提示「sma 是中心到轨道的距离，不是高度」）；`ORBITING` 时 `0 ≤ e < 1`；倾角 0..180 |
| `FlightLog` | `PLANNED` 时不能有 `actual_date`；`LAUNCHED`/`FAILED` 时必须有 `actual_date`；`result_code` 不能 < -1 |
| `RocketStage` | 由 DB 约束管 `stage_order` 唯一 |

**`ModelForm` 默认只做字段级校验，不会调用模型的 `clean()`。** 所以：

- 用 `ModelForm` 的编辑页，**必须显式触发模型校验**。标准 `ModelForm` 其实会调用 `instance.full_clean(exclude=...)` —— 但 `exclude` 会包含所有不在表单里的字段，而 `program` 正好不在表单里，于是 `program` 的「必填」校验被跳过，**所以要在保存前手工把 `program` 设好**（见 §5.2）。模型 `clean()` 里的规则（纬度、`sma`、状态-日期）仍会照常执行。
- **不要**把 `program` 做成隐藏字段（`HiddenInput`）再让用户提交它 —— 那样 URL 里的存档能被篡改。**从 URL 或实例上取，不从表单数据取。**

## 5. 实现要点

### 5.1 新增一个「自动填 program」的混入

放在 `core/forms.py`（新建此文件）：

```python
class ProgramScopedFormMixin:
    """把 program（所属存档）从 URL/上下文注入，表单里不显示该字段。

    为什么必须显式注入：program 是必填外键且不在表单字段里，
    ModelForm._post_clean 会调用 instance.full_clean(exclude=表单外字段)，
    于是 program 的必填校验被跳过；若不注入，保存时会 IntegrityError。

    ⚠️ 属性名是 program，绝不能写成 save —— save 会遮蔽 Model.save()。
    """

    def __init__(self, *args, program=None, **kwargs):
        super().__init__(*args, **kwargs)
        self.fields.pop("program", None)          # 不显示、不接受用户输入
        if program is not None:
            self.instance.program = program       # 新建时由视图传入
```

**视图侧**：新建页从 `self.request.GET["save"]` 取存档对象传给表单；编辑页 `program` 已在实例上，不传。

### 5.2 视图的三种形态（都在各 app 的 `views.py`）

```python
class SaveScopedCreateView(CreateView):
    """/xxx/new/?save=<pk>。存档从查询参数取，不从表单取。"""
    template_name = "form.html"
    form_class = RocketForm

    def dispatch(self, request, *args, **kwargs):
        self.program = get_object_or_404(Save, pk=request.GET.get("save"))
        return super().dispatch(request, *args, **kwargs)

    def get_form_kwargs(self):
        return {**super().get_form_kwargs(), "program": self.program}

    def get_context_data(self, **kwargs):
        return {**super().get_context_data(**kwargs),
                "cancel_url": reverse("ops:workspace", args=[self.program.pk])}

    def get_success_url(self):
        messages.success(self.request, f"已新增：{self.object}")
        return reverse("ops:workspace", args=[self.program.pk])
```

**删除**（6 个）统一用 `DeleteView`：

```python
class RocketDeleteView(DeleteView):
    model = Rocket
    template_name = "confirm_delete.html"

    def form_valid(self, form):
        """PROTECT 外键会让删除抛 ProtectedError，必须转成友好提示。"""
        try:
            return super().form_valid(form)
        except ProtectedError as exc:
            names = "、".join(str(o) for o in exc.protected_objects[:5])
            messages.error(self.request, f"删除失败：仍有数据引用它（{names}），请先处理。")
            return redirect(self.get_success_url())
```

**所有删除必须是 POST**（`DeleteView` 默认如此）。**不要**在列表页用 `<a href>` 做删除链接。

## 10. 易踩的坑（逐条核对）

1. **外键写成 `save=` 而不是 `program=`** → `TypeError: 'Save' object is not callable`。`manage.py check` 与 `makemigrations` **都查不出来**，只有真实保存时才炸。§8.2 有专门的回归测试。
2. **`program` 用 `HiddenInput` 让用户提交** → 可被篡改，能把自己的火箭写进别人的存档。**必须从 URL/实例取。**
3. **`ModelForm` 不含 `program` 却不注入** → 保存时 `IntegrityError`。必须实现 `ProgramScopedFormMixin`。
4. **删除用 GET 链接** → 必须 `DeleteView`（仅 POST）+ CSRF。
5. **`DeleteView` 不捕获 `ProtectedError`** → 500。`Rocket`/`Payload`/`Site` 被 `FlightLog` 以 PROTECT 引用，删它们必然触发。
6. **删存档仍会抛 `ProtectedError`**（别的存档的日志引用了本存档的火箭/发射场）→ 必须捕获。
7. **`stage_order` 重复** → DB 有 `UniqueConstraint`，但要让用户看到中文提示而不是 500。
8. **忘了 POST-Redirect-GET** → 用户刷新会重复提交。
9. **`rocket.save` 模板 bug** → Django 静默输出空串，页面不报错但内容缺失。用 `assertContains` 卡住。
10. **不要开 `USE_THOUSAND_SEPARATOR`** → 数字输入框变 `NaN`。
11. **列表页缺 `select_related`** → N+1 查询。工作台页要 `select_related("body")` / `select_related("rocket", "site")` 等。
